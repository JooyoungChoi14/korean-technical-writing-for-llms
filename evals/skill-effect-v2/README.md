# 스킬 발견과 지침 효과를 분리한 실험

이 실험은 다음 세 문장을 서로 다른 사실로 취급합니다.

1. CLI가 스킬을 발견했다.
2. 모델이 응답을 끝까지 반환했다.
3. 스킬의 지침 때문에 원하는 판단이 더 자주 나왔다.

앞선 [CLI 스모크 테스트](../cli-smoke/README.md)는 1번과 한 차례의 기대 행동을 확인했습니다. 이번 실험은 네이티브 스킬 로더를 사용하지 않고 같은 지침을 Responses API의 `instructions`에 넣어 3번을 따로 측정합니다. 따라서 이 결과를 “Ollama 모델이 Agent Skill을 직접 사용했다”고 해석하면 안 됩니다.

## 무엇을 바꿨나

현재 스킬을 기준선으로 고정하고 두 개의 작은 후보 지침만 만들었습니다.

- `certainty`: 원문으로 확정되지 않는 구현을 채워야만 수정안이 성립하면, 수정하지 않고 최소 확인 질문을 남긴다.
- `conflict`: 규칙의 출처·효과·우선순위를 분해하고, 앞선 허용과 뒤선 거부가 동시에 성립하는 정확한 조합을 대입한다.
- `combined`: 두 후보를 함께 적용한다.

개발 세트에서는 `none`, 현재 스킬 `baseline`, 두 단독 후보와 결합 후보를 비교했습니다. 보류 세트에서는 개발 결과가 가장 나았던 `combined`와 `baseline`만 비교했습니다. 후보 파일은 실제 스킬과 분리했으며, 채택 기준을 통과하기 전에는 배포 스킬을 수정하지 않았습니다.

## 문항과 실행 조건

개발·보류 세트는 각각 12문장입니다.

- 뜻을 확정할 수 없는 물체 비유 3개
- 명확해서 그대로 통과해야 하는 문장 5개
- 나열 순서와 일반 우선 원칙이 충돌하는 규칙 3개
- 뜻은 알 수 있지만 명사로 압축된 문장 1개

보류 세트는 개발 세트와 다른 산업과 명사를 사용합니다. 예를 들어 개발 세트의 정산·가격·알림 대신 감사 로그·재고·임상 연구를 사용했습니다. 모델에는 기대 판정과 실험 목적을 주지 않았습니다.

| 항목 | 값 |
|---|---:|
| 모델 | 8개 |
| 개발 조건 | 5개 |
| 반복 | 조건별 3회 |
| 개발 호출 | 120회 |
| 보류 호출 | 48회 |
| 합계 | 168회 |
| temperature | 0 |
| 지침 포함 조건의 최대 출력 | 16,384토큰 |

모델 목록과 정확한 조건은 [`design.json`](design.json), 문항과 기대 행동은 [`tasks/`](tasks/)에 있습니다.

## 실행 중 발견한 환경 실패

성능 실험 전에 두 가지 실행 실패가 있었습니다.

1. Windows PowerShell 5가 BOM 없는 UTF-8 스크립트의 한글 리터럴을 ANSI로 읽어 입력과 출력이 깨졌습니다. 이후 실행을 PowerShell 7(`pwsh`)로 고정했습니다.
2. 12문항과 현재 스킬 전체를 8,192 출력 토큰 안에서 처리하게 하자 최종 텍스트 없이 한도를 소진했습니다. 지침 포함 조건은 16,384토큰으로 다시 실행했습니다.

두 실패는 [`pilot-failures/`](pilot-failures/)에 보존했습니다. 내용 오판 점수에는 포함하지 않았습니다. 본 실행에서도 빈 응답은 정확도 0점으로 섞지 않고 완료율로 따로 기록했습니다.

## 개발 세트 결과

| 조건 | 완료율 | 선별 점수 | 판단 정확도 | 명확 문장 오탐 | 근거 없는 구현 추가 | 정확한 충돌 질문 |
|---|---:|---:|---:|---:|---:|---:|
| none | 95.8% | 55.6% | 55.3% | 0.0% | 35.1% | 15.8% |
| baseline | 87.5% | 60.3% | 55.6% | 0.0% | 17.5% | 7.9% |
| certainty | 83.3% | 60.7% | 55.8% | 0.0% | 13.3% | 1.7% |
| conflict | 87.5% | 57.8% | 52.9% | 0.0% | 20.0% | 10.0% |
| combined | 87.5% | 60.7% | 59.9% | 0.0% | 11.1% | 22.2% |

`combined`는 목표 오류 두 가지를 동시에 줄이는 방향을 보였습니다. 그러나 종합 선별 점수는 기준선보다 0.4%p 높을 뿐이었고, 8개 모델 중 4개에서 개선·3개에서 악화·1개에서 변화가 없었습니다. 단독 `conflict` 후보는 오히려 전체 성능을 낮췄습니다.

## 보류 세트 결과

| 조건 | 완료율 | 선별 점수 | 판단 정확도 | 명확 문장 오탐 | 근거 없는 구현 추가 | 정확한 충돌 질문 |
|---|---:|---:|---:|---:|---:|---:|
| baseline | 87.5% | 50.4% | 51.6% | 6.7% | 33.3% | 0.0% |
| combined | 83.3% | 53.5% | 56.3% | 5.0% | 36.7% | 10.0% |

결합 후보는 충돌 사례와 판단 정확도에서 개선 방향을 유지했지만, 완료율이 4.2%p 낮아졌고 근거 없는 구현 추가는 3.4%p 늘었습니다. 선별 점수 개선도 3.1%p로 사전 기준인 10%p에 미치지 못했습니다.

### 좋아진 사례: 정확한 충돌 조합을 질문함

원문:

> 현장 관리자 공개, 본사 보안 비공개, 문서 소유자 공개, 기본 비공개 순으로 적용하고 비공개를 우선합니다.

Kimi K3의 기준선은 “나열 순서와 비공개 우선 중 무엇이 먼저인가”라는 일반 질문을 남기면서도, 비공개 우선으로 규칙을 다시 써 버렸습니다. 결합 후보는 수정안을 만들지 않고 다음과 같이 물었습니다.

> 현장 관리자이면서 본사 보안 대상인 사용자에게는 문서가 공개됩니까, 비공개됩니까? 나열 순서로는 공개이지만, 비공개 우선 원칙으로는 비공개이므로 두 규칙이 충돌합니다.

후보가 의도한 연산 절차가 실제 출력에 나타난 사례입니다.

### 해결되지 않은 사례: 구현을 질문하면서도 먼저 확정함

원문:

> 재고 부족을 흡수할 쿠션이 필요합니다.

같은 모델의 결합 후보 출력은 `쿠션`의 뜻을 묻기는 했지만, 수정안에서는 먼저 “안전 재고를 확보해야 한다”고 확정했습니다. Qwen 3.5도 `Safety Stock`을 사실처럼 넣었습니다. 즉 “모르면 묻기” 규칙을 읽은 것과, 수정안에서 추정을 실제로 멈춘 것은 다른 성공 조건입니다.

## 채점의 의미와 한계

[`score_skill_effect.py`](../../scripts/score_skill_effect.py)는 다음 항목을 기계적으로 선별합니다.

- 응답·JSON·문항 수가 유효한가
- 기대 판정과 일치하는가
- 명확한 문장을 불필요하게 고치지 않았는가
- 질문에 충돌하는 정확한 두 규칙이 함께 등장하는가
- 수정안이 원문의 필수 의미를 보존하는가
- 문항별로 금지한 구현을 사실처럼 추가하지 않았는가

이 점수는 의미 평가 전체를 대체하지 않습니다. 정확한 동의어, 더 미묘한 의미 변경, 문장 자연스러움은 자동 점수만으로 확정할 수 없습니다. 원출력과 문항별 판정은 [`results/`](results/)에 함께 공개합니다.

## 결론: 이번 후보는 배포 스킬에 넣지 않음

사전 채택 기준은 보류 세트 +10%p, 명확 문장 오탐과 근거 없는 추론의 비악화, 8개 중 최소 4개 모델 개선, 반복 방향의 안정성이었습니다. 결합 후보는 모델 수 조건만 충족했고 나머지 핵심 조건을 충족하지 못했습니다.

따라서 이번 실험에서는 실제 [`SKILL.md`](../../plugins/korean-technical-writing-review/skills/korean-technical-writing-review/SKILL.md)를 수정하지 않았습니다. 확인된 교훈은 다음 후보를 더 짧게 만드는 데 사용합니다.

1. 수정안과 확인 질문을 동시에 내지 말고, 의미가 미확정이면 수정안 필드를 반드시 `null`로 두게 한다.
2. 충돌 점검은 일반 편집 절차 전체에 붙이기보다 규칙 문장으로 분류된 경우에만 실행한다.
3. 긴 참고자료 전체를 매번 인라인하기보다 과제에 필요한 절차만 선택해 전달하는 방식을 비교한다.

## 재현

PowerShell 7에서 실행합니다.

```powershell
pwsh -NoProfile -Command "& './scripts/run_skill_effect_factorial.ps1' `
  -Models @('kimi-k3','glm-5.3-flash','glm-5.2','kimi-k2.6','deepseek-v4-flash:0731','qwen3.5:397b','gemma4:31b','gpt-oss:120b') `
  -TaskSet development `
  -Variants @('none','baseline','certainty','conflict','combined') `
  -RunCount 3 `
  -OutputRoot 'evals/skill-effect-v2/results' `
  -Concurrency 8 `
  -MaxOutputTokens 16384"
```

```powershell
python scripts/score_skill_effect.py `
  --tasks evals/skill-effect-v2/tasks/development.json `
  --results evals/skill-effect-v2/results/development `
  --output evals/skill-effect-v2/results/development/screening.json
```

API 키는 환경 변수 `OLLAMA_API_KEY` 또는 사용자 로컬 비밀 파일에서만 읽으며 결과와 메타데이터에는 저장하지 않습니다.
