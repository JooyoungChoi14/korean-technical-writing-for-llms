# 긴 문맥은 어색한 문장의 뜻을 얼마나 더 잘 복원하게 하는가

짧은 문장만 제시한 평가에서는 모델이 실제 문서라면 앞뒤에서 얻었을 정보를 사용할 수 없습니다. 이 실험은 같은 비유 문장을 네 종류의 긴 문맥에 넣고, 현재 스킬 지침을 시스템 또는 개발자 지침으로 제공했을 때 판단이 어떻게 달라지는지 확인합니다.

## 질문

검토 대상은 다음 세 문장입니다.

> 권한을 담아낼 그릇이 필요합니다.
>
> 재고 부족을 흡수할 쿠션이 필요합니다.
>
> 통계 값을 화면으로 끌어올릴 손잡이를 추가합니다.

각 문장은 네 문맥에서 반복됩니다.

- **불충분:** 관련 업무는 설명하지만 비유의 정확한 뜻은 결정하지 않았습니다.
- **충분:** 객체, 수량, 함수와 동작을 명시해 비유를 한 가지 뜻으로 바꿀 수 있습니다.
- **무관:** 긴 설명은 있지만 검토 대상 문장을 해석할 정보는 없습니다.
- **충돌:** 서로 양립할 수 없는 두 정의가 모두 현재안으로 남아 있습니다.

문맥 한 건은 418~524자, 평균 464자입니다. 모델 호출 한 번에는 같은 조건의 세 문단을 함께 넣었으므로 문맥 본문은 평균 약 1,390자입니다. 문항과 기대 판정은 [`tasks.json`](tasks.json)에 있습니다.

## 실행 조건

2026년 9월 2일 Claude Code 2.0.73과 Codex CLI 0.151.0-alpha.7.2에서 열 모델을 실행했습니다. 모델 ID와 계열의 위치는 [Claude 모델 선택 안내](https://platform.claude.com/docs/en/docs/about-claude/models/choosing-a-model)와 [OpenAI 모델 안내](https://developers.openai.com/api/docs/models/gpt)를 참고하되, 실제 사용 가능 여부는 각 CLI 호출의 성공으로 확인했습니다.

| CLI | 모델 지정값 |
|---|---|
| Claude Code | `claude-fable-5`, `claude-opus-5`, `sonnet`, `claude-haiku-4-5` |
| Codex CLI | `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna`, `gpt-5.5`, `gpt-5.4-mini`, `gpt-5.3-codex-spark` |

각 모델에 `none`과 `baseline`을 한 번씩 적용했습니다. `none`은 공통 과제와 출력 계약만 주고, `baseline`은 현재 배포 스킬의 `SKILL.md`와 세 참고 문서를 Claude의 추가 시스템 지침 또는 Codex의 개발자 지침에 넣습니다. 네이티브 스킬 발견 여부가 아니라 **동일한 지침 내용의 효과**를 비교하려는 설계입니다.

총 80회 호출에서 12개 문맥 사례를 240번 판정했습니다. 네 조건, 두 지침 조건, 열 모델을 모두 교차했으며 최종 전송 완료율은 100%였습니다. 각 칸을 한 번만 실행했으므로 반복 안정성이나 모델의 일반적인 우열을 주장하지 않습니다.

## 결과

자동 선별 점수는 기대 판정, 문맥의 정확한 직접 인용, 필요한 확인 질문, 수정안의 필수 용어, 금지된 추정의 부재를 같은 비중으로 계산합니다. 검토 대상 문장을 그대로 되풀이한 인용은 문맥 근거로 인정하지 않고, 가능한 해석을 확인 질문에 열거한 것은 근거 없는 확정으로 세지 않습니다. 자연스러움 전체를 대신하는 점수가 아니라 원출력을 찾기 위한 진단 지표입니다.

| 문맥 | 지침 없음 | 현재 스킬 | 차이 | 판단 정확도 차이 |
|---|---:|---:|---:|---:|
| 불충분 | 66% | 74% | +8%p | +30%p |
| 충분 | 81% | 85% | +4%p | +30%p |
| 무관 | 81% | 77% | -4%p | +10%p |
| 충돌 | 93% | 93% | 0%p | 0%p |
| **전체** | **80%** | **82%** | **+2%p** | **+18%p** |

지침이 없을 때도 충분한 문맥의 점수는 불충분 문맥보다 15%p 높았고, 판단 정확도는 37%에서 70%로 33%p 높았습니다. 따라서 짧은 문장만 사용한 골든셋은 실제 문서에서 얻을 수 있는 회복 가능성을 과소평가할 수 있다는 가설을 지지합니다.

그러나 문맥의 길이만으로는 부족합니다. 무관 문맥은 길어도 뜻을 확정할 근거가 되지 않았고, 충돌 문맥에서는 정보가 많을수록 하나를 임의로 선택하지 않는 절차가 필요했습니다.

### 스킬은 특히 “모르면 고치지 않기”에 도움이 됨

불충분한 권한 문맥에서 Opus 5의 무지침 출력은 아직 저장 방식이 정해지지 않았는데도 다음 수정안을 만들었습니다.

> 사용자 직접 설정, 소속 부서, 과제 역할, 임시 위임과 적용 기간을 반영해 미리 계산한 메뉴 권한 결과를 보관할 구조가 필요하다.

스킬을 적용한 출력은 같은 문맥의 미결정 문장을 근거로 인용하고 수정안을 만들지 않았습니다.

> “저장 위치와 자료 구조, 이름, 생성 주체는 아직 결정하지 않았다.”
>
> 제안 수정안: `null`

이 차이는 문장을 더 자연스럽게 바꾸는 능력보다, 문맥이 허용하지 않는 구체화를 중단하는 능력에 가깝습니다.

### 충분한 문맥에서는 지침 없이도 강한 모델이 잘함

충분한 문맥에서 Fable 5와 Opus 5의 무지침 점수는 모두 100%였습니다. 현재 스킬을 적용한 점수는 두 모델 모두 93%였습니다. 한 번의 실행에서는 강한 모델에 문맥만 정확히 제공해도 높은 성능이 나왔고, 스킬의 추가 이득은 작거나 일부 세부 채점에서 오히려 줄었습니다.

따라서 스킬의 가치는 모든 문장을 더 잘 고치는 만능 향상보다 다음 경계 행동에 있습니다.

1. 문맥이 충분하면 그 안의 용어로 비유를 구체화합니다.
2. 문맥이 불충분하거나 무관하면 구현을 만들지 않고 질문합니다.
3. 문맥이 충돌하면 어느 정의를 쓸지 확인하기 전에는 수정하지 않습니다.

### 긴 전체 스킬은 일부 모델에 부담이 될 수 있음

Haiku 4.5의 판단 정확도는 50%에서 83%로 높아졌지만 전체 점수는 70%에서 67%로 낮아졌고, 문맥 직접 인용률은 75%에서 25%로 떨어졌습니다. gpt-5.3-codex-spark도 판단 정확도는 42%에서 75%로 높아졌지만 문맥 직접 인용률은 33%에서 0%로 낮아졌습니다. 두 모델의 스킬 적용 출력에는 문맥의 판단 근거 대신 검토 대상 문장 자체를 다시 인용한 사례가 있었습니다.

Fable 5에서도 종합 점수가 88%에서 85%로 낮아졌습니다. Fable은 문맥 직접 인용을 유지했지만 충분한 문맥의 수정안이 자동 채점의 필수 용어를 모두 포함하지 못했고, 불충분한 문맥에서 기대한 보류 판정이 늘지 않았습니다. 이는 모델의 일반 성능이 높다는 사실과 이 편집 절차의 지시를 더 정확히 따른다는 사실이 같지 않음을 보여 줍니다.

따라서 경량 모델에는 전체 참고 문서를 한꺼번에 넣기보다 과제에 필요한 세 규칙만 전달하는 축약형 지침을 따로 시험할 가치가 있습니다. 최고 성능 모델에는 불필요한 형식 제약을 줄인 최소 지침과 무지침 문맥 조건을 함께 비교해야 합니다. 이번 결과만으로 축약형을 배포 스킬에 추가하지는 않습니다.

## 결론

사용자의 가설은 조건부로 맞았습니다. 전후 문맥이 실제 정의를 포함하면 짧은 문장만 제시할 때보다 모델이 뜻을 더 잘 복원했습니다. 동시에 다음 두 한계도 확인했습니다.

- 긴 문맥이 **관련 있고 일관돼야** 합니다. 무관하거나 충돌하는 정보는 답이 아닙니다.
- 스킬은 강한 모델의 충분 문맥 성능을 크게 올리기보다, 불충분한 문맥에서 성급한 수정을 막는 안전장치로 더 유용했습니다.

따라서 다음 평가는 짧은 회귀 문항을 버리는 대신 두 층으로 구성하는 편이 좋습니다. 짧은 문항은 특정 오류를 빠르게 찾는 단위 시험으로 유지하고, 긴 문맥 문항은 뜻을 복원하거나 보류하는 통합 시험으로 사용합니다.

## 재현과 원자료

실행기는 [`run_context_effect_cli.ps1`](../../scripts/run_context_effect_cli.ps1), 채점기는 [`score_context_effect.py`](../../scripts/score_context_effect.py)입니다. 최종 80개 출력과 메타데이터는 [`cli-results/`](cli-results/)에 있습니다.

```powershell
& .\scripts\run_context_effect_cli.ps1 `
  -Conditions underspecified,sufficient,irrelevant,conflicting `
  -Variants none,baseline `
  -ProfileKeys claude-fable-5,claude-opus-5,claude-sonnet,claude-haiku-4-5,codex-gpt-5.6-sol,codex-gpt-5.6-terra,codex-gpt-5.6-luna,codex-gpt-5.5,codex-gpt-5.4-mini,codex-gpt-5.3-codex-spark `
  -OutputRoot evals\context-effect-v3\cli-results `
  -Concurrency 2 `
  -SkipFinished

python scripts\score_context_effect.py `
  --tasks evals\context-effect-v3\tasks.json `
  --results evals\context-effect-v3\cli-results `
  --output evals\context-effect-v3\cli-results\scores.json
```

Ollama Cloud에서도 더 많은 모델을 실행하려 했지만 낮은 동시성과 재시도 후에도 제공자 429가 이어졌습니다. 이를 내용 실패로 채점하지 않고 [`pilot-failures/`](pilot-failures/)에 실행기·인코딩 문제와 함께 분리했습니다. API 키와 인증 정보는 결과에 저장하지 않았습니다.
