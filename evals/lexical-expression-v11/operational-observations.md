# 응답 처리 관찰

## GLM 5.3의 T052·T054 N 교정

실행기의 오류명은 `JSONDecodeError`이지만, 응답 내부의 JSON 객체 자체가 깨진 사례는 아니다. 서비스는 `completed`를 반환했고, 유효한 JSON 코드 블록 뒤에 설명문을 덧붙였다. 실행기는 전체 응답 또는 전체를 감싼 코드 블록만 허용하므로 파싱하지 못했다. 출력 한도 소진이나 교정 능력 부족과 구분한다.

사후에 로컬에서 코드 블록만 추출하자 파싱됐고, 교정문은 정상 대조문 원문과 같았다. 재호출은 하지 않았으며 원래 실패 기록도 유지했다. 이 복구본은 사전 실행기 기준의 주 분석 쌍에는 넣지 않았다. 후속 파서가 단일 JSON 블록과 부가 설명을 구분하도록 보완할 근거는 되지만, 이번 도중에 성공 기준을 바꾼 것은 아니다.

이후 T054 N 교정에서도 같은 형식이 반복됐다. 블록 내부 JSON은 유효하고 원문을 유지했지만, 뒤따른 설명문 때문에 전체 응답 파싱이 실패했다. 두 건 모두 별도 사후 복구 기록으로 남겼다. 따라서 이 두 건은 JSON 객체 구문 오류가 아니라 요청한 단독 JSON 형식 미준수와 엄격한 파서가 결합한 실패다.

## 출력 한도를 지정하지 않은 경우의 한계

DeepSeek의 첫 문항 N/NS 진단은 서비스 응답이 `incomplete`였고 종료 이유는 `max_output_tokens`였다. 클라이언트 요청에는 출력 한도 필드가 없었다. 따라서 한도 미지정은 서비스 기본 한도까지 없어진다는 뜻이 아니다. GLM 5.3의 첫 문항 NS 교정에는 별도의 시간 초과가 있었다.

위 실패들은 문항별로 분리했다. 실패 진단의 교정만 생략하고 다른 문항과 모델은 계속 처리했다. 실패를 언어 평가의 패배로 세지 않는다.
