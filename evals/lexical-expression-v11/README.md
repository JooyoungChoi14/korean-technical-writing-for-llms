# v11: 단건 N/NS 비교

상태: 실제 실행·56쌍 잠정 검토·검증 완료. 238회 호출, JSON 파싱 성공 233회, 429 발생 0회. 진단 실패에 따른 교정 2회는 생략했다. 기존 준비본과 별도로 실행 입력과 코드를 고정했으며 실행 중 바꾸지 않았다.

[결과 표](results.md) · [결과 해석](interpretation.md) · [진단 관찰](diagnostic-observations.md) · [응답 처리 관찰](operational-observations.md) · [집계 JSON](results-summary.json)

기존 T001, T006, T033, T048 후보와 T052, T054 대조문을 각 1건씩 처리한다. N(자연스러운 한국어)과 NS(같은 요청 + 수정 스킬)를 각 1회, 진단 후 교정 순서로 비교한다. 원문·문맥·출력 형식은 동일하다. 문항과 모델 순번에 따라 N/NS 선후를 교차한다. 사후 선택한 작은 표본이며 일반 개선율로 확대하지 않는다.

10개 요청 모델: Claude CLI claude-sonnet-4-5-20250929; Codex CLI gpt-5.5, gpt-5.6-sol, gpt-5.6-terra; Ollama Cloud deepseek-v4-pro:0813, kimi-k3, qwen3.5:397b, glm-5.2, glm-5.3, glm-5.3-flash. 이는 10개 서비스 제공자가 아니라 3개 서비스 경로의 10개 요청 모델이다.

모델명은 요청값을 기준으로 표시한다. Claude CLI 사용량에는 요청한 Sonnet 외에 Haiku·Opus 항목도 기록되어 있어 순수 Sonnet API 실험으로 부르지 않는다. Codex CLI의 실제 처리 모델은 별도로 검증하지 못했고, system 지침과 요청을 사용자 프롬프트로 함께 전달했다. Ollama는 Responses 요청의 instructions와 input으로 전달했다. 따라서 주된 비교는 같은 경로 안의 N/NS이며 서비스 간 순위를 매기는 실험이 아니다.

최대 6문항 × 2조건 × 2단계 × 10경로 = 240회. 클라이언트 출력 한도 미지정, 호출 대기시간 360초, 자동 재시도 없음. 경로별 401/403/429 또는 3회 연속 실패 시 중단한다. 문항별 형식 실패는 다른 문항을 차단하지 않는다. 실제 원문·스킬과, 교정 단계에 전달하는 동일 모델의 고정 진단이 전송 범위다. 별도 외부 채점이나 저장소 원문 공개는 하지 않는다.

사용자의 간격 요청에 따라 각 서비스(Claude/Codex/Ollama)별 동시 요청은 1개, 응답 후 다음 요청까지 최소 10초로 제한했다. Ollama 모델 6개가 같은 큐를 공유하며, 각 서비스에서 429를 받으면 그 서비스의 나머지 요청을 실행하지 않는다. 간격은 계정 사용량 한도의 회피 수단이 아니며 429 부재를 보장하지 않는다.

진단은 교정 전에 저장·해시 고정한다. 정확 일치/공백 차이/문맥에만 존재/원문에 없음으로 위치를 구분하고, 마지막 두 유형은 수정 근거로 쓰지 않도록 동일한 안내를 N/NS 교정 요청에 넣는다. 진단 내용은 고치지 않는다. keep/clarify의 replacement는 null 또는 문자열을 허용한다. 대응 누락은 기록하되 반환된 교정문을 버리지 않는다. 이 절차의 결과는 위치 검사 안내를 포함한 작업 흐름의 효과이며 진단 설명을 요구하지 않는 일반 교정과 동일하지 않다.

분석은 같은 문항·모델에서 N/NS 결과가 모두 있는 쌍을 대상으로 한다. 진단의 문제 판정·유보·위치 오류, 교정의 표현 개선·의미 보존·새 문제를 분리한다. 형식 준수와 모델 품질을 혼동하지 않는다. AI 잠정 검토는 독립적 사람 판정으로 취급하지 않는다.

NS는 고정된 스킬 본문을 요청 지침에 추가한 조건이다. 도구가 스킬을 자동으로 발견·선택·로딩하는 운용 효과는 시험하지 않았다. 같은 후보 4개를 여러 모델에서 반복했으므로 모델·문항 쌍의 수를 독립적인 문항 수로 간주하지 않는다. 이번 결과로 문서 전반의 개선율이나 일반화 성능을 추정하지 않는다.
