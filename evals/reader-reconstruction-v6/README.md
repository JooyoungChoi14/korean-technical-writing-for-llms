# 사람의 문체 선호 없이도 수정문의 설명 책임을 측정할 수 있는가

## 결론: 후보 지침은 문장의 주체와 동작을 더 드러냈지만, 빠진 사실까지 안정적으로 복원하지는 못했다

v5의 현행·후보 출력 가운데 두 조건 모두 교차 판정이 끝난 164쌍을 비교했다. 후보 지침을 적용하면 문장만으로 주체와 동작을 알 수 있는 비율은 37.2%에서 47.6%로 10.4%p 높아졌다. 그러나 두 판정자가 모두 확인한 최소 명제 복원율은 32.6%에서 35.1%로 2.5%p만 높아졌고, 필요한 명제를 전부 복원한 문장 비율은 14.0%에서 13.4%로 0.6%p 낮아졌다.

| 지표 | 현행 | 후보 | 차이 | 사전 기준 |
|---|---:|---:|---:|---:|
| 엄격 명제 복원율 | 32.6% | 35.1% | +2.5%p | +5%p 이상 |
| 완전 복원율 | 14.0% | 13.4% | -0.6%p | +3%p 이상 |
| 주체·동작 명시율 | 37.2% | 47.6% | +10.4%p | 탐색 지표 |
| 판정자 일치율 | 92.2% | 91.8% | -0.4%p | 각 조건 80% 이상 |
| 이상 표현 제거율 | 80.5% | 82.9% | +2.4%p | v5 보조 지표 |

사전에 정한 두 개선 폭을 모두 충족하지 못했으므로 메타 평가 신호는 [`scores.json`](scores.json)의 `no_signal`이다. 이 결과는 v5의 `hold` 결정을 바꾸지 않는다.

## 무엇을 다르게 물었는가

사람에게 “어느 문장이 더 자연스러운가”를 물으면 평가자의 취향과 전문 지식이 결과에 섞인다. 이번에는 선호 판단을 버리고 더 좁은 질문을 만들었다.

> 수정문만 읽은 판정자가, 실행 전에 정해 둔 최소 명제를 모두 확인할 수 있는가?

예를 들어 `모든 행을 먼저 검사하고 전부 유효할 때만 저장한다`는 문장을 평가할 때는 다음 명제를 따로 판정했다.

1. 업로드 서비스가 저장 전에 모든 행을 검사한다.
2. 한 행이라도 유효하지 않으면 아무 행도 저장하지 않는다.
3. 모든 행이 유효할 때만 하나의 트랜잭션으로 저장한다.

판정자에게는 원 생성 모델, 현행·후보 조건과 기대 결론을 숨겼다. 수정문과 명제만 보여 주고, 문장에 직접 적혀 있거나 모호하지 않게 바꾸어 말한 명제만 `true`로 답하게 했다. 명제 목록을 보고 생략된 내용을 추론해서는 안 된다고 명시했다.

## 어떻게 자기 평가와 한 모델의 취향을 줄였는가

v5의 720개 수정 결과를 다시 생성하지 않고 그대로 사용했다. 각 결과는 원 생성 모델과 다른 두 계열이 판정하도록 설계했다.

- Claude 출력은 Codex와 Ollama 계열이 판정한다.
- Codex 출력은 Claude와 Ollama 계열이 판정한다.
- Ollama 출력은 Claude와 Codex가 판정한다.

두 판정자가 모두 `true`라고 답한 명제만 엄격 복원으로 셌다. 한 명 이상이 확인한 경우는 민감도 분석에만 사용했다. 최소 명제, 블라인드 순서와 판정 기준은 결과 생성 전 커밋 `208c12c`에 고정했다.

## 실제 문장에서는 무엇이 달라졌는가

후보가 주체·동작뿐 아니라 빠진 사실도 되살린 경우가 있었다.

| 현행 | 후보 | 확인된 변화 |
|---|---|---|
| 각 기관의 권한 설정을 합쳐 사용자별 유효 메뉴 권한을 만든다. | 사용자가 속한 기관의 권한 설정과 공통 역할 설정에서 허용 메뉴를 합쳐 사용자별 유효 메뉴 권한으로 저장한다. | 공통 역할, 허용 메뉴, 저장 동작이 돌아왔다. |
| 주문 서비스는 재고 예약에 실패한 주문 번호를 `inventory-retry` 토픽에 발행한다. | 주문 서비스는 재고 예약에 실패한 주문 번호를 `inventory_retry_requested` 이벤트로 만들어 Kafka의 `inventory-retry` 토픽에 발행한다. | 이벤트 이름과 발행 대상이 함께 남았다. |
| 업로드 서비스는 모든 행을 먼저 검사하고, 유효한 행만 트랜잭션으로 저장한다. | 업로드 서비스는 모든 행의 유효성을 먼저 검사하고, 모든 행이 유효할 때만 하나의 트랜잭션으로 수강 대상자를 저장한다. | 일부 행만 저장한다는 의미 변형을 바로잡았다. |

반대 사례도 반복됐다. 후보 지침이 문장을 풀어 쓰더라도 결론이나 호환 조건을 떨어뜨렸다.

| 현행 | 후보 | 빠진 내용 |
|---|---|---|
| 두 권한을 하나의 세션 값으로 합치면 구현은 단순해지지만, 조직 이동 뒤 로그아웃할 때까지 이전 조직의 행을 볼 수 있어 두 권한을 분리한다. | 두 권한을 하나의 세션 값으로 합치면 구현은 단순해지지만, 조직 이동 뒤 로그아웃할 때까지 이전 조직의 행을 볼 수 있다. | 두 권한을 분리한다는 결론 |
| 서버는 기존 엔드포인트와 두 필드를 유지하면서 선택 필드 `preferredName`을 추가한다. 구버전 앱은 이 필드를 무시하고 신버전 앱만 값이 있을 때 별칭을 표시한다. | 서버는 기존 엔드포인트와 두 필드를 유지하면서 선택 필드 `preferredName`을 추가하며, 신버전 앱만 값이 있을 때 별칭을 표시한다. | 구버전 앱의 처리 방식 |

같은 수정문인데도 실행 위치에 따라 판정이 달라진 사례도 있었다. 이는 LLM 판정이 완전한 의미 검증기가 아니며, 높은 전체 일치율만으로 개별 판정의 안정성이 보장되지는 않는다는 경고다.

## 실행 중 드러난 평가 환경의 문제

처음에는 판정 60개를 한 요청에 넣었다. 이 크기는 판정 내용과 무관한 실패를 만들었다.

- Claude Fable 5는 일부 요청에서 32,000 출력 토큰 한도를 넘거나 정책 필터 오탐으로 거부했다.
- Kimi K3는 60개와 20개 묶음에서 최종 JSON 전에 20,000 출력 토큰을 소진했다.
- Kimi K3는 10개와 5개 묶음 일부를 완료했지만, 병렬 복구에서는 429가 발생했다.
- 동시성을 1로 낮추고 225초 동안 재시도한 뒤 GLM 5.3 Flash로 모델을 바꿔도 429가 계속돼 제공자 수준 제한으로 분류했다.

항목, 명제와 순서는 바꾸지 않고 전송 단위만 Claude·Codex 20개, Kimi 10개 이하로 줄였다. Fable이 한 항목만 보내도 거부한 누락분은 CLI가 권고한 Claude Sonnet으로 판정했다. 실제 모델은 모든 메타데이터에 남겼다. Codex 판정 504개와 Claude 역할 판정 504개는 모두 확보했지만, Ollama 역할은 432개 중 120개에서 멈췄다.

따라서 전체 720개를 그대로 비교하지 않았다. 현행과 후보가 모두 두 판정을 가진 동일 모델·실행·사례 164쌍만 주결과에 사용했다. 이 가운데 144쌍은 Ollama 원출력이고, Claude·Codex 원출력은 20쌍뿐이다. 표본이 Ollama 원출력에 치우쳤으므로 열 모델 전체의 평균 효과로 일반화할 수 없다.

## 이 메타 평가가 말해 주는 것

“수정문 안에 빠짐없이 되돌려 놓는다”는 한 줄은 모델이 문장의 겉골격을 명시하게 만드는 데에는 영향을 줬다. 하지만 무엇이 최소 사실인지 먼저 추출하고 수정 뒤 하나씩 대조하는 절차를 만들지는 못했다. 그래서 주체와 동작은 더 잘 보이지만 조건·범위·결론의 완전성은 좋아지지 않았다.

다음 후보는 자연스럽게 쓰라는 강조문이 아니라 다음 절차여야 한다.

1. 수정 전에 검토 문장이 전달해야 하는 최소 명제를 적는다.
2. 각 명제를 주체·동작·대상·조건·결과로 구분한다.
3. 수정 뒤 명제별로 문장에 명시됐는지 대조한다.
4. 빠진 명제가 있으면 문장을 짧게 만드는 작업을 중단한다.

이번에는 이 절차를 시험하지 않았으므로 배포 스킬에는 넣지 않는다. 또한 자동 판정만으로 “한국어 독자가 더 자연스럽게 느낀다”고 주장하지 않는다. 이번 결과가 지지하는 범위는 사전에 정의한 최소 명제가 문장만으로 확인되는지까지다.

## 재현 자료

- 사전 계획: [`protocol.md`](protocol.md)
- 최소 명제: [`minimum-propositions.json`](minimum-propositions.json)
- 블라인드 배치와 원출력 대응표: [`batches/manifest.json`](batches/manifest.json)
- 판정 출력과 실행 메타데이터: [`judge-results/`](judge-results/)

- 집계 결과: [`scores.json`](scores.json)

```powershell
python scripts/build_reader_reconstruction_batches.py `
  --scores evals/naturalness-tuning-v5/scores-patterns.json `
  --propositions evals/reader-reconstruction-v6/minimum-propositions.json `
  --output evals/reader-reconstruction-v6/batches

python scripts/score_reader_reconstruction.py `
  --manifest evals/reader-reconstruction-v6/batches/manifest.json `
  --judge-results evals/reader-reconstruction-v6/judge-results `
  --v5-scores evals/naturalness-tuning-v5/scores-patterns.json `
  --output evals/reader-reconstruction-v6/scores.json
```
