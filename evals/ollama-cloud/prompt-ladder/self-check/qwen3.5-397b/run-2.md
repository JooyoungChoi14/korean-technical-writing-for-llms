## 요약
- **구체화 필요 2 건**, **통과 1 건**
- 가장 큰 독해 부담: 1 번 문장의 비유적 표현 (`그릇`) 과 3 번 문장의 평가 논리 (`순서` vs `거부 우선`) 모호성

| 위치 | 원문 | 독자가 추측해야 하는 정보 | 판정 | 수정안 | 확인할 사실 |
|---|---|---|---|---|---|
| 1 번 문장 | 권한을 담아낼 그릇이 필요합니다. | `그릇` 이 지칭하는 기술적 실체 (토큰, 세션, 테이블 등) | 구체화 필요 | 권한 정보를 저장할 **세션 객체 (또는 토큰)** 가 필요합니다. | 권한을 저장하는 실제 데이터 구조나 매커니즘은 무엇입니까? |
| 3 번 문장 | 사용자 직접 거부... 순으로 적용해 거부를 우선합니다. | 규칙 일치 시 평가 중단 여부, `거부 우선` 의 적용 범위 (전체 규칙 중 하나라도 거부인가, 순서상 먼저 만난 거부인가) | 구체화 필요 | 규칙은 **사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순으로 검사하며, 일치하는 규칙 중 거부가 있으면 허용보다 우선합니다.** | 규칙 평가는 첫 번째 일치 규칙으로 중단합니까, 아니면 모든 규칙을 수집하여 거부가 있는지 확인합니까? |

## 통과 문장
- **2 번 문장:** `임시 권한은 만료 시각을 저장하고 각 요청에서 현재 시각과 비교해 유효성을 확인합니다.`
  - 주체 (시스템) 가 생략되었으나 기술 문서에서 허용되는 객체 중심 서술이며, 동작 (저장, 비교, 확인) 과 조건 (만료 시각, 현재 시각) 이 명확합니다.

## 의미 확인 필요
- 3 번 문장의 수정안에서 `일치하는 규칙 중` 이라는 표현을 추가했으나, 실제 구현이 `First Match` 인지 `Deny Overrides` 인지 개발팀의 의도 확인이 필요합니다.
