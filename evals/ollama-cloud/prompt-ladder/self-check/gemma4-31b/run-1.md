## 요약
- 구체화 필요 2건, 통과 1건
- 가장 큰 독해 부담: 동작을 대신하는 비유(`그릇`)와 주체가 생략된 압축적 나열(`~순으로 적용`)로 인해 실제 구현 방식(데이터 구조 및 로직)을 독자가 추측해야 함.

| 위치 | 원문 | 독자가 추측해야 하는 정보 | 판정 | 수정안 | 확인할 사실 |
|---|---|---|---|---|---|
| 문장 1 | 권한을 담아낼 그릇이 필요합니다. | '그릇'이 의미하는 실제 기술적 대상(클래스, DB 테이블, 객체, 변수 등)과 그 역할 | 구체화 필요 | 권한 정보를 저장하고 관리할 [데이터 구조/객체]가 필요합니다. | '그릇'이 구체적으로 어떤 구현체(예: PermissionContainer, Table 등)를 의미하는가? |
| 문장 2 | 임시 권한은 만료 시각을 저장하고 각 요청에서 현재 시각과 비교해 유효성을 확인합니다. | - | 통과 | - | - |
| 문장 3 | 사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순으로 적용해 거부를 우선합니다. | 권한을 판정하는 주체(시스템/모듈)와 '적용'의 구체적인 동작(우선순위 평가 방식) | 구체화 필요 | [권한 판정 모듈]은 '사용자 직접 거부 $\rightarrow$ 사용자 직접 허용 $\rightarrow$ 역할 거부 $\rightarrow$ 역할 허용' 순으로 권한을 확인하며, 거부 설정이 있을 경우 이를 최우선으로 적용합니다. | 권한을 판정하는 주체는 무엇이며, 나열된 순서가 우선순위가 높은 순서가 맞는지 확인 필요 |
