## 요약
- 구체화 필요 2건, 의미 확인 필요 1건
- 가장 큰 독해 부담: 1번 문장의 비유적 표현(‘그릇’)으로 인해 필요한 기술적 구현체가 완전히 가려짐

| 위치 | 원문 | 독자가 추측해야 하는 정보 | 판정 | 수정안 | 확인할 사실 |
|---|---|---|---|---|---|
| 1 | 권한을 담아낼 그릇이 필요합니다. | 어떤 자료 구조·테이블·객체·스키마 필드가 필요한가? 누가 생성·관리하는가? | 구체화 필요 | 권한을 저장할 자료 구조(예: 정책 테이블, 권한 객체, 스키마 필드)가 필요합니다. | 어떤 저장소·스키마·객체 타입을 의도하는지 |
| 2 | 임시 권한은 만료 시각을 저장하고 각 요청에서 현재 시각과 비교해 유효성을 확인합니다. | (비교적 명확) 주체가 ‘임시 권한’ 자체가 아니라 시스템/검증 로직임을 명시하면 더 정확 | 통과 | — | — |
| 3 | 사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순으로 적용해 거부를 우선합니다. | ‘적용해’의 구체적 알고리즘: 첫 매칭 즉시 종료인지, 전수 평가 후 거부 우선인지? ‘사용자 직접’과 ‘역할’은 어떻게 구분되는지(출처·우선순위)? | 의미 확인 필요 | 평가 순서: 사용자 직접 거부 → 사용자 직접 허용 → 역할 거부 → 역할 허용. **첫 매칭 시 종료** / **전수 평가 후 거부 우선** 중 어느 방식인지 명시 필요. | 평가 알고리즘(쇼트서킷 여부), ‘사용자 직접’과 ‘역할’ 권한의 출처·구분 기준 |

---

### 문제 없는 문장 (별도 표시)
- **2번**: 동작(저장, 비교, 확인), 대상(만료 시각, 현재 시각), 조건(각 요청)이 문장 안에서 모두 명시되어 있어 독자가 추측할 요소가 거의 없습니다. 단, 주어를 ‘시스템이’ 또는 ‘검증 로직이’로 바꾸면 행위 주체가 더 명확해집니다.
