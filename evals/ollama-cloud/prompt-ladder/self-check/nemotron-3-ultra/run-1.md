## 요약
- 구체화 필요 2건, 통과 1건
- 가장 큰 독해 부담: 1번 문장에서 기술적 구현체가 은유로만 제시됨

| 위치 | 원문 | 독자가 추측해야 하는 정보 | 판정 | 수정안 | 확인할 사실 |
|---|---|---|---|---|---|
| 1 | 권한을 담아낼 그릇이 필요합니다. | '그릇'이 가리키는 구체적 자료 구조·클래스·테이블·스키마·인터페이스 중 무엇인가 | 구체화 필요 | 권한을 저장할 자료 구조(또는 클래스·테이블·스키마)가 필요합니다. | 어떤 구현체(클래스명, 테이블명, 인터페이스명)를 의도했는지 |
| 2 | 임시 권한은 만료 시각을 저장하고 각 요청에서 현재 시각과 비교해 유효성을 확인합니다. | (추측 불필요: 주체·동작·조건·결과가 문장 내에 모두 명시됨) | 통과 | — | — |
| 3 | 사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순으로 적용해 거부를 우선합니다. | '적용해'가 가리키는 구체적 연산(평가·병합·필터·우선순위 판정 등)과 '거부를 우선한다'의 구현 방식(첫 거부 시 즉시 차단? 최종 결과만 거부?) | 구체화 필요 | 권한 평가 시 사용자 직접 거부 → 사용자 직접 허용 → 역할 거부 → 역할 허용 순으로 규칙을 평가하고, 거부 규칙이 하나라도 매치되면 즉시 차단한다. | 평가 시점(요청마다? 캐시 여부?), '거부 우선'의 정확한 동작(첫 매치 즉시 차단 vs 전체 평가 후 거부 우세) |
