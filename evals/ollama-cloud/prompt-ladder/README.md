# 실행 환경 문제와 프롬프트 문제를 분리한 반복 실험

처음 Codex와 Ollama Cloud를 연결했을 때 MiniMax 두 모델과 Qwen은 도구 정의를 거부했고, Mistral은 서비스 고부하 오류를 냈습니다. 이 결과만 보면 모델이 한국어 검토 과제를 수행하지 못한 것처럼 보입니다. 그러나 도구를 제거하고 같은 모델의 OpenAI 호환 Responses API를 직접 호출하자 네 모델 모두 답변을 만들었습니다. 최초 실패는 한국어 능력이 아니라 **Codex 하네스가 전달한 도구 스키마 또는 당시 서비스 상태의 문제**였습니다.

실행만 성공하게 만든 뒤에는 다른 문제가 드러났습니다. 같은 스킬을 주어도 많은 모델이 `그릇`을 임의의 자료 구조로 확정하거나, 명확한 문장을 다시 고치거나, 권한 규칙의 구체적인 교차 충돌을 찾지 못했습니다. 그래서 두 번째 실험에서는 같은 19개 모델에 프롬프트를 다섯 단계로 바꾸어 각각 3회 실행했습니다.

결과는 단순하지 않았습니다. 일반적인 자체 점검이나 반례 생성 지침은 기준선보다 좋아지지 않았고, 오히려 완전 통과가 줄었습니다. `사용자 직접 허용 + 역할 거부`라는 과제별 조합을 직접 지정했을 때만 57회 중 21회가 통과했습니다. 이 실험 범위에서는 **실행 환경을 고친 것만으로 내용 문제가 해결되지 않았으며, 일반 지침만으로도 충분히 개선되지 않았습니다. 과제의 핵심 경계 사례를 프롬프트가 직접 지목하면 일부 모델이 회복했습니다.**

## 무엇을 같은 조건으로 두었나

- 날짜: 2026-09-02
- 모델: Ollama Cloud에서 조회한 19개 모델
- 호출: `https://ollama.com/v1/responses`, 도구 없음
- 입력: 동일한 설치 스킬 전문과 동일한 세 문장
- 생성 조건: `temperature: 0`, `max_output_tokens: 16384`
- 반복: 모델·프롬프트 조건마다 3회
- 총 호출: 285회, 답변 270회, 빈 답변 15회, API 오류 0회
- 판정: [`expected.json`](../../cli-smoke/expected.json)의 세 조건을 모두 만족해야 통과

모델별 원문, 소요 시간과 토큰 수는 각 조건 디렉터리에 있습니다. 인증 키, 계정 정보와 로컬 절대 경로는 저장하지 않았습니다.

## 다섯 단계에서 실제로 추가한 지침

기준선은 설치 스킬만 사용했습니다. 이후 단계는 앞선 조건에 문장을 추가했으며, 실행 코드는 [`run_ollama_prompt_ladder.ps1`](../../../scripts/run_ollama_prompt_ladder.ps1)에 있습니다.

### 1. 기준선

추가 지침 없음.

### 2. 자체 점검

```text
1. 같은 문장을 요약에서는 통과시키고 표에서는 문제로 판정하는 등 답변 내부의 판정이 충돌하지 않아야 합니다.
2. 원문에서 확정할 수 없는 구현체·자료 구조·정책을 수정안에 사실처럼 추가하지 말고, 필요한 최소 확인 질문을 남기세요.
```

### 3. 일반 반례

```text
여러 규칙의 적용 순서와 일반적인 우선 원칙이 함께 제시되면, 서로 다른 범주의 규칙 두 개가 동시에 성립하는 반례를 만들어 최종 결과가 하나로 결정되는지 검사하세요. 결정할 수 없다면 그 구체적인 규칙 조합을 확인 질문에 명시하세요.
```

### 4. 교차 범주 반례

```text
서로 다른 출처나 범주의 규칙이 우선순위로 나열되고 허용·거부처럼 반대 결과가 섞여 있으면, 앞선 범주의 허용과 뒤 범주의 거부가 동시에 성립하는 조합을 반드시 대입하세요. 나열 순서와 일반 우선 원칙이 서로 다른 결과를 만들면 그 조합과 최종 결과를 확인 질문에 명시하세요.
```

### 5. 과제별 경계 사례

```text
권한 규칙을 검토할 때 사용자에게 직접 부여된 허용과 역할에서 부여된 거부가 동시에 성립하는 경우를 대입해 최종 결과가 무엇인지 확인하세요. 원문으로 결정할 수 없다면 이 조합을 그대로 질문으로 남기세요.
```

마지막 단계는 일반적인 작성 지침 후보가 아니라 진단용 조건입니다. 기대 행동의 핵심 사례를 직접 알려 주므로, 이 결과만으로 스킬의 일반 성능이 좋아졌다고 볼 수 없습니다.

## 결과를 어떻게 해석했나

### 1. 최초 실행 실패 네 건은 환경 문제였다

MiniMax M2.7, MiniMax M3, Mistral Large 3와 Qwen 3.5는 최초 Codex 실행에서 최종 답변을 만들지 못했습니다. 도구를 보내지 않은 직접 API 반복에서는 네 모델 모두 답변을 만들었습니다. 따라서 최초 결과는 내용 점수 0점이 아니라 하네스 호환성 또는 일시적 서비스 실패로 남겨야 합니다.

### 2. 일반적인 지침 강화는 효과가 재현되지 않았다

자체 점검, 일반 반례, 교차 반례는 모두 기준선 7회보다 완전 통과가 적었습니다. 지침이 더 구체적이고 길어졌다는 사실만으로 경계 사례 선택 능력이 좋아지지 않았습니다. 일부 응답은 교차 충돌을 정확히 찾았지만 `그릇`을 자료 구조로 먼저 확정해 C1에서 실패했습니다. 한 기준을 강조하면서 다른 기준을 놓치는 현상도 있었습니다.

이 때문에 교차 반례 문구를 현재 스킬의 필수 지침으로 바로 편입하지 않았습니다. 한 과제에서 집계 성능을 낮춘 문장을 일반 해결책으로 배포할 근거가 부족합니다.

### 3. 과제별 힌트는 일부 모델을 분명히 구제했다

과제별 조건에서 DeepSeek Flash, GLM 5.1, GLM 5.2, Kimi K2.6과 Kimi K3는 3회 모두 통과했습니다. 적어도 이 실행들의 기준선 실패는 환경 문제만으로 설명할 수 없습니다. 모델은 조합을 직접 지목받았을 때 기대 행동을 수행할 수 있었고, 기준선에서는 **어떤 규칙 조합을 반례로 선택해야 하는지**를 스스로 좁히지 못했습니다.

반대로 Gemma, 두 GPT-OSS, 두 MiniMax, Mistral, 세 Nemotron과 Qwen은 과제별 힌트에서도 한 번도 완전 통과하지 못했습니다. 이들에게는 더 긴 지침이 아니라 문장별 판정을 강제하는 출력 구조, 독립 검증 단계 또는 다른 모델이 필요할 수 있습니다.

### 4. 출력 안정성은 내용 점수와 별개다

GLM 5.3과 GLM 5.3 Flash는 기준선의 비어 있지 않은 출력에서 강했지만, 전체 15회 중 각각 9회와 6회가 빈 답변이었습니다. 반대로 항상 답변을 만든 모델도 내용 기준을 계속 놓쳤습니다. 따라서 ‘응답을 안정적으로 반환하는가’와 ‘반환한 답변이 세 기준을 만족하는가’를 한 점수로 합치지 않았습니다.

MiniMax M3의 일부 응답에는 최종 검토문보다 훨씬 긴 내부 추론성 텍스트가 포함됐습니다. 이것도 한국어 판정 정확도와 구분해야 할 운영상 문제입니다.

## 지금 채택할 방지책

이번 결과는 특정 권한 예시를 스킬에 하드코딩하라는 뜻이 아닙니다. 현재 증거로 권장할 수 있는 절차는 다음과 같습니다.

1. 하네스 실패와 내용 실패를 먼저 분리한다. 최종 답변이 없으면 도구 없는 직접 호출로 모델 자체를 다시 확인한다.
2. 규칙 문장은 검토 모델의 자유로운 반례 선택에만 맡기지 않는다. 작성자가 알고 있는 핵심 경계 사례를 평가 세트에 명시한다.
3. 초안 모델과 독립 검증 모델을 분리한다. 비유 대상 확정, 정상 문장 오탐, 교차 규칙 충돌을 각각 판정한다.
4. 스킬 변경은 단일 성공 사례가 아니라 반복 집계가 기준선보다 좋아질 때만 채택한다.
5. 빈 출력과 추론 노출을 의미 정확도와 별도의 운영 지표로 기록한다.

## 재현

API 키는 저장소 밖의 `OLLAMA_API_KEY` 환경 변수 또는 로컬 비밀 파일에 둡니다. 모델 목록은 배열로 전달합니다.

```powershell
.\scripts\run_ollama_prompt_ladder.ps1 `
  -Models @('deepseek-v4-flash:0731', 'glm-5.3-flash') `
  -Variant baseline `
  -RunCount 3 `
  -Concurrency 2 `
  -OutputRoot .\evals\ollama-cloud\prompt-ladder
```

`Variant`는 `baseline`, `self-check`, `counterexample`, `cross-boundary`, `task-specific` 중 하나입니다. 각 실행을 [`judgment-prompt.ko.txt`](judgment-prompt.ko.txt)로 판정한 뒤 다음 명령으로 집계합니다.

```powershell
.\scripts\summarize_ollama_prompt_ladder.ps1 `
  -ExperimentRoot .\evals\ollama-cloud\prompt-ladder `
  -OutputPath .\evals\ollama-cloud\prompt-ladder\aggregate.json
```

## 한계

- 하나의 세 문장 과제만 사용했으므로 다른 기술 문서로 일반화할 수 없습니다.
- 조건별 3회는 프롬프트 민감도를 탐색하기 위한 최소 반복이지 정밀한 성능 추정치가 아닙니다.
- `temperature: 0`에서도 제공자 구현과 모델에 따라 출력이 달랐습니다.
- 판정은 Codex gpt-5.6-sol이 수행했고 통과·실패 대표 사례를 사람이 다시 확인했습니다. 완전한 사람 다중 평정은 아닙니다.
- 과제별 조건은 기대 사례를 직접 포함하므로 독립적인 일반화 성능 시험이 아닙니다.
- 토큰과 실행 시간은 당시 서비스 상태, 추론량과 출력 길이의 영향을 함께 받습니다.

이 결과는 모델 순위표가 아닙니다. 같은 실패처럼 보이는 현상을 실행 환경, 경계 사례 선택, 지침 준수와 출력 안정성으로 나누어 다음 하네스 변경의 근거를 만드는 실험입니다.
