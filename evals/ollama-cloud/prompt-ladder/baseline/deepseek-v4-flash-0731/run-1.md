## 요약
- 구체화 필요 1건, 의미 확인 필요 1건, 통과 1건
- 가장 큰 독해 부담: 문장 3의 나열 순서와 "거부 우선" 원칙이 서로 모순될 가능성이 있어, 실제 권한 평가 규칙을 추측해야 합니다.

| 위치 | 원문 | 독자가 추측해야 하는 정보 | 판정 | 수정안 | 확인할 사실 |
|---|---|---|---|---|---|
| 문장 1 | 권한을 담아낼 그릇이 필요합니다. | "그릇"이 구체적으로 무엇인지(변수, 데이터 구조, DB 필드, 토큰 클레임 등)와 어떤 동작(저장, 보관)을 의미하는지 | 구체화 필요 | 권한 정보를 저장할 필드(또는 데이터 구조)가 필요합니다. | 권한을 실제로 저장하는 대상이 무엇인가? |
| 문장 3 | 사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순으로 적용해 거부를 우선합니다. | "순으로 적용"이 첫 번째 일치 항목을 적용하는지, 마지막 일치 항목을 적용하는지. 나열 순서상 사용자 직접 허용이 역할 거부보다 앞서므로 "거부 우선"이라는 결론과 충돌할 수 있음 | 의미 확인 필요 | (거부 우선이 맞다면) 사용자 직접 거부, 역할 거부, 사용자 직접 허용, 역할 허용 순으로 우선순위를 적용합니다. <br> (나열 순서가 맞다면) 사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순서로 첫 번째 일치 항목을 적용합니다. (단, 이 경우 사용자 직접 허용이 역할 거부보다 우선하므로 '거부 우선'은 성립하지 않습니다.) | 실제 권한 평가는 첫 번째 일치 항목을 적용하는가? 사용자 직접 허용과 역할 거부가 충돌할 때 어느 쪽이 우선하는가? |

## 통과 문장
- **문장 2**: 임시 권한은 만료 시각을 저장하고 각 요청에서 현재 시각과 비교해 유효성을 확인합니다. — 대상(임시 권한), 동작(저장, 비교, 확인)이 명확하며 독자가 추가로 추측할 정보가 없습니다.
