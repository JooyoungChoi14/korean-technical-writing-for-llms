## 요약
- 구체화 필요 1건(문장 1), 의미 확인 필요 1건(문장 3), 통과 1건(문장 2)
- 가장 큰 독해 부담: 문장 3. 네 항목의 나열 순서와 '거부 우선'이 어떤 평가 절차를 뜻하는지 문장만으로 확정할 수 없어, 독자가 권한 충돌 해결 규칙을 스스로 재구성해야 합니다.

| 위치 | 원문 | 독자가 추측해야 하는 정보 | 판정 | 수정안 | 확인할 사실 |
|---|---|---|---|---|---|
| 문장 1 | 권한을 담아낼 그릇이 필요합니다. | '그릇'이 가리키는 실제 대상(필드·테이블·모델 등)과 필요한 동작(추가·저장). 비유가 대상과 동작을 대신함 | 구체화 필요 | 권한 정보를 저장할 데이터 구조가 필요합니다. | 권한을 저장하는 실제 대상은 무엇인가? '필요합니다'가 신규 추가를 뜻하는가, 기존 구조 활용인가? |
| 문장 3 | 사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순으로 적용해 거부를 우선합니다. | 네 항목이 '규칙의 출처와 효과'라는 점, '적용'의 실제 동작(순서대로 검사해 첫 일치를 따르는지, 전부 평가해 거부가 하나라도 있으면 거부인지). 명사 나열에 주체·서술어가 없음 | 의미 확인 필요 | 권한 규칙을 ① 사용자에게 직접 설정한 거부 → ② 사용자에게 직접 설정한 허용 → ③ 역할을 통해 받은 거부 → ④ 역할을 통해 받은 허용 순으로 검사해, 가장 먼저 일치하는 규칙으로 허용 여부를 결정합니다. (첫 일치 해석 기준) | 사용자 직접 허용(②)과 역할 거부(③)가 동시에 일치하면 어느 쪽이 우선하는가? 순서대로 처리하면 허용이 되어 '거부 우선'과 어긋납니다. 일치하는 규칙이 없을 때 기본값은 허용인가, 거부인가? |

## 통과
- 문장 2: 대상(임시 권한), 저장 값(만료 시각), 검사 시점(각 요청), 비교 대상(현재 시각), 결과(유효성 확인)가 문장 안에 모두 있어 독자가 채울 정보가 없습니다. 비교 주체(서버 등)가 생략되어 있으나 관용적으로 자연스럽게 읽혀 지적하지 않았습니다.
