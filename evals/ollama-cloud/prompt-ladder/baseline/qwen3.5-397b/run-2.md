## 요약
- 구체화 필요 2 건, 의미 확인 필요 0 건
- 가장 큰 독해 부담: 비유 (그릇) 와 주체 혼동 (권한이 저장/검증함) 으로 인해 실제 구현 단위와 동작 주체를 추측해야 함

| 위치 | 원문 | 독자가 추측해야 하는 정보 | 판정 | 수정안 | 확인할 사실 |
|---|---|---|---|---|---|
| 문장 1 | 권한을 담아낼 그릇이 필요합니다. | '그릇'이 지칭하는 실제 구현체 (객체, 테이블, 필드 등) | 구체화 필요 | 권한 정보를 저장할 **[구조체/테이블/필드]** 가 필요합니다. | 권한 데이터를 실제로 보유하는 단위는 무엇입니까? |
| 문장 2 | 임시 권한은 만료 시각을 저장하고 각 요청에서 현재 시각과 비교해 유효성을 확인합니다. | 저장 및 검증 동작을 수행하는 실제 주체 (시스템, 모듈, 토큰 등) | 구체화 필요 | 임시 권한 **[레코드/토큰]** 에 만료 시각을 저장하며, **[시스템]** 이 각 요청에서 현재 시각과 비교해 유효성을 확인합니다. | 만료 시각이 저장되는 물리적 단위는 무엇이며, 검증 로직은 어디에 위치합니까? |

## 통과한 문장
- **문장 3:** `사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순으로 적용해 거부를 우선합니다.`
  - **이유:** 권한 평가 우선순위와 적용 순서가 명확하며, 기술 문서에서 허용 가능한 수준의 명사 압축입니다. (단, '사용자 직접'이 프로젝트 내 정의된 용어라면 통과입니다.)
