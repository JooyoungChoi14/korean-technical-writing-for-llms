## 요약
- 구체화 필요 2건, 의미 확인 필요 1건
- 가장 큰 독해 부담: 1번 문장의 비유가 드러내는 동작이 원문에서 드러나지 않음

| 위치 | 원문 | 독자가 추측해야 하는 정보 | 판정 | 수정안 | 확인할 사실 |
|---|---|---|---|---|---|
| 1 | 권한을 담아낼 그릇이 필요합니다. | 그릇이 무엇인가(토큰·세션·레코드 등)? 담아낸다는 동작이 구체적으로 무엇인가? | 구체화 필요 | `권한 정보를 저장할 구조가 필요합니다.` | "그릇"이 참조하는 구현체의 실제 이름과 역할이 무엇인가? |
| 2 | 임시 권한은 만료 시각을 저장하고… | — | 통과 | — | — |
| 3 | 사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순으로 적용해 거부를 우선합니다. | 순으로 적용한다는 것이 평가 우선순위인지 실제 적용 순서인지? 적용한다는 동작이 구체적으로 무엇인가? | 의미 확인 필요 | `사용자 직접 거부 → 사용자 직접 허용 → 역할 거부 → 역할 허용 순으로 평가하며, 거부는 허용을 덮어씁니다.` | 이 규칙이 어떤 맥락(UI 렌더링·API 응답 필터링·DB 쿼리 조건 등)에서 적용되는가? |

## 의미 확인 필요 상세

**3번 문장 —** `"순으로 적용"`: 평가(가장 높은 우선순위부터 확인)와 실제 처리(가장 낮은 우선순위부터 덮어쓰기)는 반대 방향이다. 원문의 방향을 잘못 해석하면 권한 판정 로직의 부호가 역전된다. 문서 사용자가 코드를 읽는 독자라면 코드 주석이나 함수 시그니처와 대조할 것을 권한다.
