## 요약
- 구체화 필요 2건, 의미 확인 필요 1건
- 가장 큰 독해 부담: 1번 문장의 비유(“그릇”)가 대상 자료구조를 전혀 드러내지 않음

| 위치 | 원문 | 독자가 추측해야 하는 정보 | 판정 | 수정안 | 확인할 사실 |
|---|---|---|---|---|---|
| 1 | 권한을 담아낼 그릇이 필요합니다. | 어떤 자료구조·객체·필드·테이블이 권한을 보관하는가? “담아낸다”는 저장·참조·전달 중 무엇인가? | 구체화 필요 | 권한을 보관할 자료구조(객체/필드/테이블)가 필요합니다. | 권한을 저장할 구체적 엔티티 이름이 프로젝트에 이미 정해져 있는가? |
| 2 | 임시 권한은 만료 시각을 저장하고 각 요청에서 현재 시각과 비교해 유효성을 확인합니다. | 주체(임시 권한 객체 자신인가? 별도 검증 모듈인가?), 만료 시각 저장 위치, 비교 실패 시 처리 | 의미 확인 필요 | 임시 권한 객체는 만료 시각을 저장하고, 요청 처리 시 현재 시각과 비교해 유효 여부를 판단한다. | 만료 시각 저장 주체와 비교·판단 주체가 동일 객체인가? 비교 실패 시 동작(거부/예외/로그)은 별도 명세에 있는가? |
| 3 | 사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순으로 적용해 거부를 우선합니다. | “적용해”가 의미하는 연산(AND/OR/첫 매칭 중단/우선순위 합산), 평가 대상이 단일 요청인가 다중 규칙 셋인가 | 구체화 필요 | 권한 평가 시 사용자 직접 거부 → 사용자 직접 허용 → 역할 거부 → 역할 허용 순으로 규칙을 검사하고, 먼저 매칭된 거부 규칙이 있으면 즉시 거부한다. | 평가가 첫 매칭에서 중단되는가(short-circuit)? 허용 규칙이 나중에 나와도 거부를 뒤집지 않는가? |

### 통과 문장
- 없음 (세 문장 모두 검토 대상에 해당)
