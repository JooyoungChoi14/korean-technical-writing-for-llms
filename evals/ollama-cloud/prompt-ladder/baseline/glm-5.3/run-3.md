## 요약
- 구체화 필요 0건, 의미 확인 필요 2건, 통과 1건(문장 2)
- 가장 큰 독해 부담: 문장 3 — 나열한 순서(사용자 직접 허용이 역할 거부보다 앞)와 "거부를 우선"이 서로 다른 결과를 내는 두 읽기를 모두 허용하여, 규칙이 겹칠 때 최종 판정을 원문만으로 확정할 수 없다.

| 위치 | 원문 | 독자가 추측해야 하는 정보 | 판정 | 수정안 | 확인할 사실 |
|---|---|---|---|---|---|
| 문장 1 | 권한을 담아낼 그릇이 필요합니다. | ① "그릇"의 실제 대상(테이블·필드·자료구조·토큰 클레임 중 무엇인지) ② "담아낼"의 실제 동작(저장인지 표현·전달인지) | 의미 확인 필요 | 확인 후: `권한을 저장할 [확인된 대상]이 필요합니다.` — 비유 자리에 실제 명칭과 동작을 치환한다. | 질문: 권한을 어느 구성 요소에 어떤 형태로 보관합니까? (예: DB 테이블, 세션 필드, 자료구조) |
| 문장 3 | 사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순으로 적용해 거부를 우선합니다. | ① 네 항목의 정체(문장에는 "무엇을" 적용하는지가 없음 — 규칙인지 설정인지) ② "적용"의 실제 동작(순서대로 평가해 첫 일치 규칙을 적용하는지, 병합하는지) ③ 규칙이 여러 개 동시에 걸릴 때의 최종 결과 ④ "거부를 우선"의 의미 — 나열 순서에 대한 설명인지, 순서와 무관하게 거부가 항상 이기는 별도 규칙인지. 두 읽기는 "사용자 직접 허용 + 역할 거부" 조합에서 결과가 갈린다 | 의미 확인 필요 | 읽기에 따라 확정: (a) 첫 일치 적용이라면 `권한 판정은 사용자 직접 거부 → 사용자 직접 허용 → 역할 거부 → 역할 허용 순서로 평가하고, 먼저 일치하는 규칙을 적용한다.` — 이때 "거부를 우선합니다"는 같은 출처 안의 나열 순서에 대한 근거이므로 `같은 출처에서는 거부를 먼저 평가한다`로 바꾸거나 뺀다. (b) 거부가 항상 이긴다면 `거부 규칙이 하나라도 있으면 거부하고, 없을 때 나열한 순서대로 허용을 정한다.` | 질문: 사용자에게 직접 부여된 허용과 역할의 거부가 동시에 있을 때 최종 판정은 무엇입니까? (답이 "허용"이면 (a), "거부"이면 (b)) |

## 문제 없음
- **문장 2 — 통과.** 대상(임시 권한), 동작(만료 시각 저장, 현재 시각과 비교), 조건(각 요청), 결과(유효성 확인)가 모두 문장 안에 있으며, 비유·명사 나열·평가어 없이 실제 동작을 서술했다. 생략된 주체(시스템)는 문맥상 하나로 확정되므로 보충할 필요가 없다.
