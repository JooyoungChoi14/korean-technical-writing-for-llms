## 요약
- 의미 확인 필요 2건(1번, 3번), 구체화 필요 0건, 통과 1건(2번)
- 가장 큰 독해 부담: 3번 — 나열한 순서와 "거부를 우선합니다"가 서로 다른 판정 알고리즘을 지시할 수 있어, 독자가 충돌 상황(사용자 직접 허용 + 역할 거부)의 결과를 문장 밖에서 결정해야 합니다. 권한 판정 규칙이므로 잘못 재구성하면 그대로 오동작으로 이어집니다.

| 위치 | 원문 | 독자가 추측해야 하는 정보 | 판정 | 수정안 | 확인할 사실 |
|---|---|---|---|---|---|
| 1번 | 권한을 담아낼 그릇이 필요합니다. | "그릇"의 정체(DB 테이블, 자료구조, 토큰 구조 등), "담아낸다"의 실제 동작(저장, 표현, 전달), 담을 권한의 형태 | 의미 확인 필요 (기준 2: 비유가 대상·동작을 대신함) | 확인 결과로 대괄호를 채움: "권한을 [동작]할 [대상]이 필요합니다." 예(저장 대상으로 확인될 경우): "부여된 권한을 저장할 권한 테이블이 필요합니다." | "그릇"은 어떤 대상이며 "담아낸다"는 어떤 동작입니까? (권한을 저장하는 구조인지, 토큰 같은 형식에 표현해 전달하는 구조인지) |
| 3번 | 사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순으로 적용해 거부를 우선합니다. | "적용"의 대상(어느 판정에 이 순서를 쓰는지), "순으로 적용"의 의미(첫 일치에서 확정인지, 모두 확인한 뒤 결정하는지), "거부를 우선"의 범위(역할 거부가 사용자 직접 허용보다 강한지) | 의미 확인 필요 (적용 대상 생략 + 조건·결과 모호) | 확인 결과에 따라 둘 중 하나: ① 첫 일치 우선이면 "요청마다 사용자 직접 거부 → 사용자 직접 허용 → 역할 거부 → 역할 허용 순으로 규칙을 확인하고, 가장 먼저 일치하는 규칙을 결과로 적용한다." ② 거부가 항상 우선이면 "사용자 직접 거부 또는 역할 거부가 하나라도 있으면 거부하고, 둘 다 없을 때만 사용자 직접 허용 → 역할 허용 순으로 허용한다." | 사용자 직접 허용과 역할 거부가 동시에 존재하는 요청의 결과는 허용입니까, 거부입니까? (나열 순서가 곧 우선순위입니까, 아니면 거부가 항상 우선입니까?) |

## 통과
- **2번 — 통과.** 대상(임시 권한), 동작(만료 시각 저장, 요청마다 현재 시각과 비교), 조건(각 요청), 결과(유효성 확인)가 문장 안에 들어 있고, 두 번째 절에서 생략된 비교 대상(만료 시각)은 직전 절에서 바로 회수됩니다.
