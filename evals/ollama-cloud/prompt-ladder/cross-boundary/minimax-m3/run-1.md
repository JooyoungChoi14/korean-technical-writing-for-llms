## 요약
- 구체화 필요 1건, 의미 확인 필요 1건
- 가장 큰 독해 부담: 문장 1의 '그릇' 비유가 실제 자료구조의 속성과 연산을 가리고, 문장 3에서 '순으로 적용'과 '거부 우선'이 동시에 성립할 때의 우선순위 동작이 모호합니다.

| 위치 | 원문 | 독자가 추측해야 하는 정보 | 판정 | 수정안 | 확인할 사실 |
|---|---|---|---|---|---|
| 1 | 권한을 담아낼 그릇이 필요합니다. | 보관할 자료구조의 종류(클래스/테이블/토큰 등), 보관 대상 속성, 노출할 연산 | 구체화 필요 | 권한 정보를 보관할 자료구조가 필요합니다. 보관 대상 속성과 요청 시 호출할 연산을 함께 정의해야 합니다. | 보관 대상 속성과 제공할 연산 |
| 3 | 사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순으로 적용해 거부를 우선합니다. | '순으로 적용'과 '거부 우선'이 동시에 성립할 때, 순서대로 평가하다가 거부를 만나면 그 이후를 계속 평가하는지, 아니면 순서와 무관하게 거부 규칙이 허용 규칙을 항상 이기는지 | 의미 확인 필요 | (수정 보류) | 평가 방식(첫 매치 승리 여부), '거부 우선'의 적용 범위(순서 내 우선 vs 절대 우선) |

## 통과한 문장

- **문장 2** "임시 권한은 만료 시각을 저장하고 각 요청에서 현재 시각과 비교해 유효성을 확인합니다.": 주체(임시 권한), 저장 대상(만료 시각), 시점(각 요청), 검증 방법(현재 시각과 비교), 결과(유효성 확인)가 모두 명시되어 있어 문장 자체로 이해 가능합니다.

## 의미 확인 필요 상세

문장 3의 경우 `순으로 적용`과 `거부 우선`이 서로 다른 우선 평가 방식일 수 있어 다음과 같은 조합에 대해 원문의 의도를 확정할 수 없습니다.

| 시나리오 | 사용자 직접 허용 O, 역할 거부 O | 사용자 직접 거부 X, 역할 허용 O |
|---|---|---|
| 첫 매치 승리(순서 우선) | 허용(#2 먼저 평가) | 허용(#4까지 평가) |
| 절대 거부 우선 | 거부(역할 거부 우선) | 허용(거부 매치 없음) |
| 순서 내 거부 우선 | 거부(#2 이후 #3 평가 시 거부 우선) | 허용 |

`거부 우선`이 위 세 가지 중 어디에 해당하는지에 따라 동일 입력에서도 결과가 달라지므로, 원문만으로는 어떤 동작이 의도된 규칙인지 확정할 수 없습니다.
