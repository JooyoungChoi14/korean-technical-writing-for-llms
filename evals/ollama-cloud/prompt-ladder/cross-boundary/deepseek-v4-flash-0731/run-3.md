## 요약
- 구체화 필요 1건, 의미 확인 필요 1건, 통과 1건
- 가장 큰 독해 부담: 3번 문장에서 나열 순서와 "거부 우선" 원칙이 충돌할 수 있는 조합

| 위치 | 원문 | 독자가 추측해야 하는 정보 | 판정 | 수정안 | 확인할 사실 |
|---|---|---|---|---|---|
| 1 | 권한을 담아낼 그릇이 필요합니다. | "그릇"이 구체적으로 무엇인지 — 자료 구조, 테이블, 클래스, 필드 중 어느 것인지 | 구체화 필요 | 권한 정보를 저장하고 조회할 자료 구조가 필요합니다. | "그릇"이 의미하는 구현 대상(권한 테이블, 권한 객체 등) |
| 3 | 사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순으로 적용해 거부를 우선합니다. | 나열 순서와 "거부 우선" 중 어느 규칙이 우선하는지. 특히 사용자 직접 허용과 역할 거부가 동시에 성립할 때의 결과 | 의미 확인 필요 | (나열 순서가 우선일 때) 사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순으로 적용합니다. (거부가 항상 우선일 때) 거부가 허용보다 항상 우선하며, 같은 종류 안에서는 사용자 직접이 역할보다 우선합니다. | 사용자 직접 허용과 역할 거부가 동시에 성립하는 경우 어느 쪽이 적용되는가? |

## 통과
- 2번 문장: 주체(임시 권한), 동작(저장·비교·확인), 조건(각 요청에서)이 모두 문장 안에 명시되어 있어 독자의 재구성이 필요하지 않습니다.

## 의미 확인 필요
- 3번 문장은 나열 순서(사용자 직접 허용이 역할 거부보다 앞섬)와 "거부를 우선"이라는 일반 원칙이 서로 다른 결과를 만들 수 있습니다. 원문만으로는 사용자 직접 허용 + 역할 거부 조합의 최종 결과를 확정할 수 없습니다.
