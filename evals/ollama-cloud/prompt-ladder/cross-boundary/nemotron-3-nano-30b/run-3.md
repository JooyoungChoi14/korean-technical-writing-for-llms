## 요약
- 문제 3건 (모든 문장이 의미·대상을 불명확하게 표현)

| 위치 | 원문 | 독자가 추측해야 하는 정보 | 판정 | 수정안 | 확인할 사실 |
|------|------|--------------------------|------|--------|-------------|
| 1 | 권한을 담아낼 그릇이 필요합니다. | “그릇”이 실제 어떤 객체·컨테이너를 의미하는가? 권한을 어디에 저장해야 하는가? | 의미 확인 필요 | **권한을 저장할 컨테이너가 필요합니다.** 또는 **권한을 담을 객체가 필요합니다.** | 컨테이너의 종류(예: 데이터베이스 필드, 메모리 구조, 설정 파일 등)와 그 컨테이너가 권한을 저장하는 방식이 프로젝트 설계에 명시되어 있는가? |
| 2 | 임시 권한은 만료 시각을 저장하고 각 요청에서 현재 시각과 비교해 유효성을 확인합니다. | “만료 시각”이 어떤 값(타임스탬프 등)을 의미하는가? “각 요청”이 어떤 시점에 발생하는지(예: API 호출 시점) 명확한가? “유효성을 확인합니다”가 어떤 결과를 반환하는지(허용/거부 여부) 명시되어 있는가? | 구체화 필요 | **임시 권한은 만료 시각을 기록하고, 요청 시 현재 시각과 비교하여 유효성을 판단합니다.** | 만료 시각을 저장하는 필드 이름이 무엇인지, 현재 시각을 가져오는 로직이 어디서 실행되는지, 유효성 판단 결과를 어디에 반영하는지(예: permission 객체의 `isValid` 플래그) |
| 3 | 사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순으로 적용해 거부를 우선합니다. | “순으로 적용해 거부를 우선합니다”가 의미하는 우선순위 규칙은 무엇인가? 거부와 허용 중 어느 것이 우선하는지, 그리고 그 순서가 실제 구현에 어떻게 반영되는지(예: 체크리스트 순서) 명확한가? | 의미 확인 필요 | **사용자 직접 거부 → 사용자 직접 허용 → 역할 거부 → 역할 허용 순으로 적용되며, 거부 동작이 가장 높은 우선순위를 가집니다.** | 거부와 허용을 구분하는 로직이 코드에서 어떻게 구현되어 있는지(예: `if (userReject) reject(); else if (userAllow) allow(); …`), 그리고 이 순서가 문서에 명시된 정책과 일치하는지 |

*문제 없는 문장은 없었으므로 별도 표시를 하지 않았습니다.*
