**감사 요약**  
전체 3문장 중 모두 명확성·의미 보존에 문제가 있습니다.  
- 1문장: 메타포 “그릇”이 구체적 대상을 제시하지 않음.  
- 2문장: 주체가 누락되어 누가 저장을 하고 비교하는지 모호함.  
- 3문장: 동작 순서와 “거부를 우선합니다”의 의미가 불명확하여 누가 어떤 결정을 내리는지 알 수 없음.  

아래 표는 각 문장의 문제점과 개선안을 정리한 것입니다.

| 위치 | 원문 | 독자가 추측해야 하는 정보 | 판정 | 수정안 | 확인할 사실 |
|------|------|---------------------------|------|--------|--------------|
| 1 | 권한을 담아낼 **그릇**이 필요합니다. | “그릇”이 실제 어떤 데이터 구조·객체·변수 등을 가리키는지 | **의미 확인 필요** | 권한을 **저장**할 **구조**(예: `Map`, `Field`, `Class`)가 필요합니다. | 현재 설계에서 권한을 보관하기 위해 사용하려는 구체적인 자료형이나 객체 이름이 무엇인지 |
| 2 | 임시 권한은 **만료 시각**을 저장하고 각 요청에서 **현재 시각**과 비교해 **유효성을 확인**합니다. | 저장·비교·확인 동작을 수행하는 **주체**(코드, 시스템, 모듈 등)와 **저장되는 값의 형식**(예: `Instant`, `long`) | **구체화 필요** | 시스템은 임시 권한을 **만료 시각**(예: `expiration: Instant`)을 **저장**하고, **각 요청 시** 현재 시각과 **비교**해 **유효성을 판단**합니다. | 임시 권한 객체가 어떤 클래스에 속하는지, 만료 시각이 어떤 타입이며, 비교 로직이 어느 단계에서 실행되는지 |
| 3 | 사용자 직접 **거부**, **허용**, 역할 **거부**, **허락** 순으로 적용해 **거부를 우선**합니다. | “거부를 우선”이라는 표현이 **무엇을** 우선시하는지(거부 동작 itself, 거부 결정을 내리는 순서, 혹은 거부 결과를 우선 반영하는지)와 **적용 주체**(사용자, 역할, 시스템) | **의미 확인 필요** | 사용자 직접 **거부** → **허용** → 역할 **거부** → **허락** 순으로 적용하며, **거부 결정을** 가장 먼저 **우선**합니다. | 거부와 허용 흐름이 실제 코드에서 어떤 조건문에 해당하는지, “우선”이 의미하는 우선순위 수준(예: `if (userRejects) return;`) |

**추가 안내**  
- 모든 수정안은 **대상·동작·조건·결과**를 명시적으로 유지하면서 문장을 재구성했습니다.  
- 변경된 부분이 원문의 의미와 완전히 일치하는지 확인하기 위해 위 “확인할 사실”을 검증해 주세요.  
- 문제가 없는 문장은 없으므로 별도 표시가 필요하지 않습니다.
