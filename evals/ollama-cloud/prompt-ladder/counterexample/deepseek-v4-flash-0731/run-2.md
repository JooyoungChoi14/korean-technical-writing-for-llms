## 요약
- 구체화 필요 1건, 의미 확인 필요 1건, 통과 1건
- 가장 큰 독해 부담: 1번 문장의 비유가 실제 저장 대상을 가리고, 3번 문장의 적용 순서와 거부 우선 원칙의 논리적 관계가 충돌할 수 있습니다.

| 위치 | 원문 | 독자가 추측해야 하는 정보 | 판정 | 수정안 | 확인할 사실 |
|---|---|---|---|---|---|
| 1 | 권한을 담아낼 그릇이 필요합니다. | 권한을 실제로 보관할 구체적인 대상(자료 구조, 필드, 테이블, 클레임 등)이 무엇인지. | 구체화 필요 | 권한을 저장할 필드(또는 자료 구조)가 필요합니다. | 권한을 보관할 대상이 JWT 클레임, DB 컬럼, 세션 객체 중 무엇인지. |
| 3 | 사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순으로 적용해 거부를 우선합니다. | "순으로 적용"이 첫 일치 우선(first-match-wins)인지, "거부를 우선"이 전역적으로 허용을 덮는 규칙(deny-overrides)인지. 예를 들어 사용자 직접 허용과 역할 거부가 동시에 존재할 때 어느 쪽이 이기는지. | 의미 확인 필요 | 사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순서로 평가하며, 거부가 하나라도 존재하면 최종 결과는 거부입니다. (또는: 거부가 허용보다 항상 우선하며, 허용 간에는 사용자 직접, 역할 순으로 우선합니다.) | 사용자 직접 허용과 역할 거부가 동시에 존재할 때의 최종 결과가 무엇인지. |

## 통과 문장
- **2번 문장**: 통과. 주체(임시 권한), 동작(저장, 비교, 확인), 조건(각 요청, 현재 시각)이 모두 명확하게 드러나며 비유나 생략이 없습니다.
