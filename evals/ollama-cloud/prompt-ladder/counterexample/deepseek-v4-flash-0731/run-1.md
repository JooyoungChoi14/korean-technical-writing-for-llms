## 요약
- 구체화 필요 1건, 의미 확인 필요 1건, 통과 1건
- 가장 큰 독해 부담: 3번 문장에서 '적용 순서'와 '거부 우선'의 논리적 관계가 모호하여, 독자가 실제 평가 알고리즘(첫 일치 vs. 거부 우선)을 추측해야 합니다.

## 통과 문장
- **2번 문장**: `임시 권한은 만료 시각을 저장하고 각 요청에서 현재 시각과 비교해 유효성을 확인합니다.` — 주체(임시 권한), 동작(저장, 비교, 확인), 조건(각 요청에서)이 모두 명확하여 통과입니다.

| 위치 | 원문 | 독자가 추측해야 하는 정보 | 판정 | 수정안 | 확인할 사실 |
|---|---|---|---|---|---|
| 1 | 권한을 담아낼 그릇이 필요합니다. | '그릇'이 구체적으로 무엇을 의미하는지 (DB 테이블, 변수, 토큰 클레임 등)와 실제 동작(저장, 전달, 참조) | 구체화 필요 | 권한 정보를 저장할 데이터 구조(또는 저장소)가 필요합니다. | '그릇'이 의미하는 구체적인 저장 대상(테이블, 필드, 토큰)은 무엇입니까? |
| 3 | 사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순으로 적용해 거부를 우선합니다. | '순으로 적용'과 '거부를 우선'의 관계. 첫 번째 일치 규칙인지, 거부가 항상 우선인지. | 의미 확인 필요 | (거부 우선이 의도라면) 사용자 직접 거부와 역할 거부를 먼저 확인해 하나라도 있으면 거부하고, 없으면 사용자 직접 허용, 역할 허용 순으로 허용을 결정합니다. | 적용 규칙이 첫 번째 일치(first-match)인지, 거부 우선(deny-overrides)인지 확인 필요. 만약 첫 번째 일치라면 '거부를 우선'이라는 표현이 허용 규칙과 충돌합니다. |
