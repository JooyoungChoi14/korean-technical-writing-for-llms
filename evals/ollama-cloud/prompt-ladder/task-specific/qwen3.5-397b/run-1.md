## 요약
- **구체화 필요 2 건**, **통과 1 건**
- 가장 큰 독해 부담: 1 번 문장의 비유적 표현 (`그릇`) 과 3 번 문장의 압축된 정책 용어 (`사용자 직접 거부` 등) 가 구체적인 구현 단위와 평가 로직을 추측하게 합니다.

| 위치 | 원문 | 독자가 추측해야 하는 정보 | 판정 | 수정안 | 확인할 사실 |
|---|---|---|---|---|---|
| 1 번 문장 | 권한을 담아낼 그릇이 필요합니다. | `그릇` 이 지칭하는 기술 단위 (클래스, 테이블, 객체 등) | 구체화 필요 | 권한 정보를 저장할 **[데이터 구조/객체/테이블]** 가 필요합니다. | 권한 데이터를 실제로 보관하는 구현 단위는 무엇입니까? |
| 3 번 문장 | 사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순으로 적용해 거부를 우선합니다. | `사용자 직접 거부` 등의 정확한 정책 정의와 `적용해` 의 평가 로직 (순차 평가인지, 우선순위 규칙인지) | 구체화 필요 | **사용자에게 직접 부여된 거부 정책**, ... 순으로 평가하며, **거부 정책이 허용 정책보다 우선하여 적용됩니다**. | 1. `사용자 직접 거부` 는 명시적 거부 (Explicit Deny) 를 뜻합니까?<br>2. 사용자 허용과 역할 거부가 충돌할 때 최종 결과가 거부입니까? ## 통과 문장
- **2 번 문장:** `임시 권한은 만료 시각을 저장하고 각 요청에서 현재 시각과 비교해 유효성을 확인합니다.`
    - 대상 (임시 권한), 동작 (저장, 비교, 확인), 조건 (각 요청) 이 명확하여 추가 수정 없이 이해 가능합니다.

## 의미 보존 자체 점검
1. **판정 일관성:** 1 번과 3 번은 정보 누락 및 압축으로 `구체화 필요` 로 통일하였고, 2 번은 정보 충분하여 `통과` 로 판정했습니다.
2. **사실 추가 금지:** 1 번 문장 수정안에서 구체적인 구현체 (DB 테이블 등) 를 단정하지 않고 `[데이터 구조/객체/테이블]` 로 표기하고 확인 질문을 남겼습니다.
3. **권한 규칙 검증:** 3 번 문장 검토 시 `사용자 허용 vs 역할 거부` 충돌 시나리오를 가정하여 `거부 우선` 규칙이 명확히 적용되는지 확인 질문으로 포함했습니다.
