## 요약
- 구체화 필요 0건, 의미 확인 필요 2건(문장 1, 3), 통과 1건(문장 2)
- 가장 큰 독해 부담: 문장 3 — 나열된 평가 순서와 '거부 우선'이 어떻게 결합되는지에 따라 최종 권한 판정이 달라지는데, 원문만으로는 어느 해석이 맞는지 확정할 수 없습니다. 권한 규칙이므로 잘못 추측한 수정이 보안 의미를 바꿀 위험이 있습니다.

| 위치 | 원문 | 독자가 추측해야 하는 정보 | 판정 | 수정안 | 확인할 사실 |
|---|---|---|---|---|---|
| 문장 1 | 권한을 담아낼 그릇이 필요합니다. | '그릇'이 가리키는 실제 산출물(데이터 모델·테이블·필드 등)과 '담아내다'의 실제 동작(저장인지 표현인지) | 의미 확인 필요 | 권한 정보를 보관할 구조를 새로 마련해야 합니다. [확인 필요: 실제 구현체] | '그릇'에 해당하는 구현체는 무엇입니까? (예: 사용자 모델의 권한 필드, 별도 권한 테이블) |
| 문장 3 | 사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순으로 적용해 거부를 우선합니다. | '적용'의 실제 동작 — 먼저 일치하는 규칙이 최종 결과를 결정하는지, 아니면 전 단계를 평가한 뒤 거부가 하나라도 있으면 최종이 거부인지 | 의미 확인 필요 | 권한은 ① 사용자 직접 거부 ② 사용자 직접 허용 ③ 역할 거부 ④ 역할 허용 순으로 평가합니다. [확인 필요: 순서가 우선순위인지, 거부 우선이 순서에 앞서는 전역 규칙인지] | 사용자 직접 허용과 역할 거부가 동시에 성립할 때 최종 결과는 무엇입니까? '먼저 일치 wins' 해석이면 ② 허용이 먼저 적용되어 '거부 우선'과 모순됩니다. |

## 문제 없음
- **문장 2(통과):** 저장 대상(만료 시각), 확인 시점(각 요청), 비교 기준(현재 시각), 목적(유효성 확인)이 문장 안에 모두 제시되어 있어 독자가 채워야 할 정보가 없습니다. 주어 '임시 권한'이 동작 주체를 대신 표현한 환유이지만, 판정에 필요한 정보는 빠짐없으므로 지적하지 않습니다.
