## 요약
- 구체화 필요 2건, 통과 1건
- 가장 큰 독해 부담: 동작을 대신하는 비유(`그릇`)와 주체가 생략된 명사 나열(`사용자 직접 거부...`)로 인해 실제 구현 대상과 적용 로직을 독자가 추측해야 함.

| 위치 | 원문 | 독자가 추측해야 하는 정보 | 판정 | 수정안 | 확인할 사실 |
|---|---|---|---|---|---|
| 문장 1 | 권한을 담아낼 그릇이 필요합니다. | '그릇'이 의미하는 구체적인 구현체(클래스, DB 테이블, 객체 등)와 그 역할 | 구체화 필요 | 권한 정보를 저장하고 관리할 [데이터 구조/객체/테이블]이 필요합니다. | '그릇'이 구체적으로 무엇을 의미하는가? (예: 권한 관리 클래스, DB 스키마 등) |
| 문장 2 | 임시 권한은 만료 시각을 저장하고 각 요청에서 현재 시각과 비교해 유효성을 확인합니다. | - | 통과 | - | - |
| 문장 3 | 사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순으로 적용해 거부를 우선합니다. | 각 권한 설정의 적용 주체와 '거부를 우선한다'는 로직의 정확한 우선순위 범위 | 구체화 필요 | 권한을 [사용자 직접 거부 $\rightarrow$ 사용자 직접 허용 $\rightarrow$ 역할 거부 $\rightarrow$ 역할 허용] 순으로 검토하며, 상위 단계에서 '거부' 설정이 발견되면 즉시 최종 권한을 '거부'로 결정합니다. | 1. 적용 순서가 왼쪽에서 오른쪽으로 진행되는가? <br> 2. '거부 우선'이 전체 단계 중 하나라도 거부면 거부라는 뜻인가, 아니면 특정 단계 내에서의 우선순위인가? |
