## 요약
- 구체화 필요 2건, 의미 확인 필요 1건
- 가장 큰 독해 부담: 1번 문장의 비유(그릇)가 구체적 자료 구조나 인터페이스를 가림, 3번 문장의 평가 알고리즘(최초 일치? 전체 순회? 누적?)이 생략됨

| 위치 | 원문 | 독자가 추측해야 하는 정보 | 판정 | 수정안 | 확인할 사실 |
|---|---|---|---|---|---|
| 1 | 권한을 담아낼 그릇이 필요합니다. | 어떤 기술적 산출물(테이블, 클래스, 스키마, 저장소, 컨텍스트 객체 등)을 의미하는가? | 구체화 필요 | 권한을 저장할 자료 구조(또는 스키마, 저장소)가 필요합니다. | 어떤 저장 매체/자료 구조를 도입하려는 것인가? |
| 2 | 임시 권한은 만료 시각을 저장하고 각 요청에서 현재 시각과 비교해 유효성을 확인합니다. | (비교적 명확) | 통과 | — | — |
| 3 | 사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순으로 적용해 거부를 우선합니다. | 평가 알고리즘: 첫 번째 매칭 즉시 종료(short-circuit)인가, 전체 순회 후 거부 존재 여부만 보는가? 동일 순위 내 다중 규칙이 있을 때 어떻게 결합하는가? | 의미 확인 필요 | 평가 순서: 사용자 직접 거부 → 사용자 직접 허용 → 역할 거부 → 역할 허용. **거부 규칙이 하나라도 매칭되면 즉시 거부**한다(또는: 모든 규칙을 평가한 뒤 거부 존재 시 거부). | 평가 방식이 최초 매칭 즉시 종료인지, 전체 평가 후 집계인지? |

---

### 문제 없는 문장
- **2번**: 동작(저장, 비교, 확인), 주체(임시 권한 레코드/로직), 조건(각 요청 시), 결과(유효성 판정)가 문장 안에 모두 들어 있습니다.
