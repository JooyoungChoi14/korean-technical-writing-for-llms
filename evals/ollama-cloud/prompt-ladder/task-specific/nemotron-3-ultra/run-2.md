## 요약
- 구체화 필요 1건, 의미 확인 필요 1건, 통과 1건
- 가장 큰 독해 부담: 1번 문장의 비유(`그릇`)가 기술적 대상을 완전히 가림, 3번 문장의 평가 알고리즘(순서 우선 vs 거부 우선)이 모순될 소지가 있음

| 위치 | 원문 | 독자가 추측해야 하는 정보 | 판정 | 수정안 | 확인할 사실 |
|---|---|---|---|---|---|
| 1 | 권한을 담아낼 그릇이 필요합니다. | 어떤 자료 구조·객체·테이블·스토리지를 말하는지, 어디에 생성되며 어떤 연산(조회·갱신·만료·취소)을 지원해야 하는지 | 구체화 필요 | 권한을 저장하고 조회할 자료 구조(또는 스토리지)가 필요합니다. | 권한 항목의 스키마, 영속성 요구사항, 동시성·만료 처리 방식 |
| 2 | 임시 권한은 만료 시각을 저장하고 각 요청에서 현재 시각과 비교해 유효성을 확인합니다. | (충분히 명시됨) | 통과 | — | — |
| 3 | 사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순으로 적용해 거부를 우선합니다. | “순으로 적용”이 첫 매칭 즉시 종료(First-applicable)인지, 전체 평가 후 거부 존재 시 거부(Deny-overrides)인지, “직접”이 사용자 레벨 정책을 뜻하는지 그룹·상속과의 구분이 무엇인지 | 의미 확인 필요 | 권한 평가 순서: 1) 사용자 명시 거부, 2) 사용자 명시 허용, 3) 역할 거부, 4) 역할 허용. **평가 방식(First-applicable / Deny-overrides) 중 하나를 명시**하십시오. | 평가 알고리즘 확정, “직접”의 정의, 역할 상속·중첩 시 처리 규칙 |

---

### 통과 문장 (별도 표시)
- **2번**: 대상(임시 권한), 동작(만료 시각 저장·요청마다 현재 시각과 비교·유효성 확인), 조건(각 요청), 결과(유효성 판단)가 문장 안에서 완결됨.
