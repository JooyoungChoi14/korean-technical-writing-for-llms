## 요약
- 구체화 필요 2건, 의미 확인 필요 0건  
- 가장 큰 독해 부담: metaphor로 대체된 저장소 표현과 주체·순서가 생략된 접근제어 규칙 설명  

| 위치 | 원문 | 독자가 추측해야 하는 정보 | 판정 | 수정안 | 확인할 사실 |
|------|------|------------------------|------|--------|-------------|
| 1 | 권한을 담아낼 그릇이 필요합니다. | 어떤 구조나 메커니즘이 권한을 담을 그릇인지 (예: 토큰, 세션, 정책 객체) | 구체화 필요 | 권한을 저장할 데이터 구조(또는 토큰)가 필요합니다. | 권한을 보관하기 위해 사용하려는 구체적인 객체 또는 형식은 무엇인가? (예: JWT 토큰, 세션 저장소) |
| 3 | 사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순으로 적용해 거부를 우선합니다. | 어느 주체가 이 규칙들을 적용하는지, 그리고 exact 적용 순서가 어떻게 정의되는지 (예: 시스템이 사용자 수준 deny → 사용자 수준 allow → 역할 수준 deny → 역할 수준 allow 순으로 검사하고, deny가 발견되면 즉시 거부) | 구체화 필요 | 인가 엔진은 먼저 사용자 수준의 거부 규칙을 확인하고, 이어서 사용자 수준의 허용 규칙을 검사한다. 그다음에 역할 수준의 거부 규칙을 확인하고, 마지막으로 역할 수준의 허용 규칙을 검사한다. deny 규칙이 발견되면 즉시 접근을 거부한다. | 규칙 적용 주체(인가 엔진 등)와 deny 우선 정책이 정확히 어떻게 구현되는지 확인해야 함 (예: 어떤 라이브러리 또는 코드에서 이 순서를 따르는지). |

### 통과한 문장
- **2.** 임시 권한은 만료 시각을 저장하고 각 요청에서 현재 시각과 비교해 유효성을 확인합니다. (통과)  
  → 대상, 동작, 조건, 결과가 모두 명시되어 추가 추론이 필요 없음.
