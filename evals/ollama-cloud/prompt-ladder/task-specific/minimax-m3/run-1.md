## 요약
- 구체화 필요 1건, 의미 확인 필요 1건, 통과 1건
- 가장 큰 독해 부담: 1번의 '그릇'이라는 비유가 실제 데이터 구조/타입을 가리고, 3번의 '거부를 우선'이 적용 순서와 결합될 때 일부 조합에서 최종 결과가 확정되지 않음

| 위치 | 원문 | 독자가 추측해야 하는 정보 | 판정 | 수정안 | 확인할 사실 |
|---|---|---|---|---|---|
| 1 | 권한을 담아낼 그릇이 필요합니다. | '그릇'이 어떤 종류의 데이터 구조(클래스, 타입, 필드, 토큰, 레코드 등)를 가리키는지, 어떤 권한 항목을 담는지 | 구체화 필요 | 권한 정보를 보관할 데이터 타입/필드가 필요합니다. 담을 항목(예: 주체, 허용 작업, 만료 시각 등)은 [확인 필요] | 담아둘 권한의 항목과 표현 형식 |
| 3 | 사용자 직접 거부, 사용자 직접 허용, 역할 거부, 역할 허용 순으로 적용해 거부를 우선합니다. | '거부를 우선'이 다음 중 무엇인지: (a) 어디서든 거부가 나오면 이후 허용 무효화, (b) 같은 출처 내 거부만 우선, (c) 순서대로 적용하되 거부 결정이 최종 | 의미 확인 필요 | 사용자 직접 거부 → 사용자 직접 허용 → 역할 거부 → 역할 허용 순으로 평가하되, 평가 중 거부가 나오면 즉시 거부로 확정합니다. | 사용자 직접 허용이 있고 역할 거부도 있는 경우의 최종 결과는 거부인가? |

## 통과한 문장
- **2번** "임시 권한은 만료 시각을 저장하고 각 요청에서 현재 시각과 비교해 유효성을 확인합니다." — 주체(임시 권한), 동작(저장·비교·확인), 조건(각 요청에서) 모두 드러나 있고 동작이 비유로 대체되지 않았습니다.

## 의미 확인이 특히 중요한 부분 (3번)
- 출력 형식 안내에 따라 권한 규칙의 대표 조합을 대입해 봤습니다.
  - 대입: **사용자 직접 허용 있음 + 역할 거부 있음**
  - 원문만으로 도출: ① 사용자 직접 거부는 없음 → ② 사용자 직접 허용 발견 → ③ 역할 거부 발견. 여기서 "거부를 우선"이 단계 ②의 허용을 무효화한다면 결과는 **거부**, 그렇지 않다면 결과는 **허용**.
  - 원문으로 확정할 수 없어 이 조합 그대로 질문으로 남깁니다.
