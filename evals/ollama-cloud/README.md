# Ollama Cloud 모델별 Codex 스모크 테스트

이 실험은 같은 스킬과 같은 세 문장을 Ollama Cloud의 공개 모델 19개에 한 번씩 제공해 다음 두 질문을 확인합니다.

1. 현재 Codex CLI에서 모델이 프로젝트 로컬 스킬을 읽고 최종 답변까지 만들 수 있는가?
2. 답변이 기존 [`expected.json`](../cli-smoke/expected.json)의 세 가지 필수 행동을 모두 만족하는가?

모델의 일반적인 한국어 성능이나 우열을 측정하는 벤치마크가 아닙니다. 실행 완료 여부와 짧은 회귀 사례의 준수 여부를 확인하는 탐색적 스모크 테스트입니다.

## 실행 조건

- 날짜: 2026-09-02
- Codex CLI 0.151.0-alpha.7.2
- Ollama Cloud의 OpenAI 호환 `responses` API
- 읽기 전용 샌드박스, 임시 세션
- 설치된 프로젝트 로컬 `korean-technical-writing-review` 스킬
- 모델당 1회 실행. Mistral만 서비스 오류 후 1회 재시도

인증 키, 계정 정보, 세션 ID와 로컬 절대 경로는 기록하지 않았습니다.

## Codex 설정

[`codex-config.example.toml`](codex-config.example.toml)을 Codex 설정에 합치고 `OLLAMA_API_KEY` 환경 변수에 키를 둡니다. 키를 TOML이나 저장소 파일에 직접 쓰지 않습니다.

```powershell
$prompt = '$korean-technical-writing-review' + "`n`n" +
  (Get-Content -Raw -Encoding UTF8 .\evals\cli-smoke\prompt.ko.txt)

codex exec `
  -p ollama-cloud `
  --model 'glm-5.3-flash' `
  --sandbox read-only `
  --ephemeral `
  --ignore-rules `
  --color never `
  $prompt
```

이 Codex 버전은 Ollama의 `/v1/models` 응답을 읽을 때 기대 스키마와 다르다는 경고를 냈습니다. 모델 ID를 `--model`로 직접 지정한 실행은 계속 진행됐으므로, 경고와 실제 완료 여부를 분리해 판정했습니다.

## 엄격한 기대 행동

| 사례 | 통과 조건 |
|---|---|
| `그릇` 비유 | 실제 기술 대상을 확인하고 테이블·클래스·데이터 구조 중 하나로 임의 확정하지 않는다. |
| 만료 검사 | 대상·시점·동작이 분명한 문장을 문제로 만들지 않는다. |
| 권한 우선순위 | 나열 순서와 `거부 우선`의 충돌을 찾고, 사용자 직접 허용과 역할 거부가 함께 있을 때의 결과를 묻는다. |

일반적인 모호함을 지적했다는 이유만으로 세 번째 조건을 통과시키지 않았습니다. 구체적인 교차 충돌을 묻지 않으면 실패로 판정했습니다.

## 후속 반복 실험

최초 실행 실패와 내용 판단 실패를 분리하기 위해 도구를 제거한 Responses API 직접 호출도 수행했습니다. 19개 모델에 다섯 프롬프트 조건을 각각 3회씩 적용한 결과, 최초에 도구 스키마나 서비스 오류를 냈던 MiniMax·Mistral·Qwen도 답변을 만들었습니다. 반면 일반적인 자체 점검과 반례 생성 지침은 내용 통과율을 높이지 못했고, 과제의 구체적인 경계 사례를 지목했을 때만 일부 모델이 회복했습니다.

285회 실행의 원출력, 모델별 반복 결과, 실제 추가 지침과 해석은 [`prompt-ladder/`](prompt-ladder/README.md)에 있습니다.

## 결과에서 보이는 것

GLM 5.3과 GLM 5.3 Flash만 세 조건을 모두 만족했습니다. 두 모델은 3번 문장에서 “첫 일치 규칙”과 “전체 거부 우선”의 차이를 발견하고, 사용자 직접 허용과 역할 거부가 만날 때 어느 쪽이 이기는지 확인했습니다.

나머지 완료 모델 대부분은 `그릇`과 일반적인 우선순위 모호성은 찾았지만, 3번의 구체적인 교차 충돌까지 좁히지 못했습니다. 일부는 오히려 원문에 없는 저장 구조나 충돌 규칙을 수정안에 추가했습니다. GPT-OSS 20B는 2번을 문제없다고 요약한 뒤 같은 답변의 표에서는 다시 교정 대상으로 표시해 내부 판정도 일치하지 않았습니다.

모델 크기나 새 버전이 이 한 사례의 통과를 보장하지도 않았습니다. GPT-OSS 120B는 20B보다 나았지만 3번을 놓쳤고, Kimi K3는 3번을 문제없다고 보았습니다. 반대로 GLM 5.3 Flash는 같은 계열의 비 Flash 모델과 함께 통과했습니다.

## 실행 실패는 별도 결과다

MiniMax 두 모델과 Qwen은 답변의 내용에 도달하기 전에 Codex가 전달한 도구 정의를 Ollama 측이 거부했습니다. Mistral은 두 차례 모두 서비스 고부하 오류를 반환했습니다. 따라서 이 네 모델은 0점이 아니라 미채점으로 남겼습니다. 현재 조합의 에이전트 운용 적합성은 확인하지 못했지만, 한국어 문장 판단 능력이 낮다고 결론내릴 근거는 없습니다.

## 한계와 다음 실험

- 모델별 1회 출력이므로 재현율과 변동성을 추정할 수 없습니다.
- 스킬 미적용 대조군이 없어 스킬이 만든 향상 폭을 계산할 수 없습니다.
- 세 문장의 엄격한 회귀 시험이므로 복잡한 문서 전체의 품질을 대표하지 않습니다.
- 완료 시간과 토큰 사용량은 실행 로그에서 관찰했지만 제공자별 계측 형식이 일정하지 않아 순위표로 만들지 않았습니다.

다음 단계는 통과·실패 모델 일부를 골라 스킬 미적용·적용 조건을 반복하고, 모델명을 가린 평가자가 탐지율·오탐률·의미 변경률을 비교하는 것입니다.
