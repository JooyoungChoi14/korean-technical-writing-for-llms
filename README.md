# Korean Technical Writing for LLMs

LLM이 만든 한국어 기술 문서를 **문법 오류가 아니라 독자가 부담하는 재해석 비용**의 관점에서 검토하는 공개 실험과 Agent Skill입니다.

> 문장이 틀리지 않았더라도, 독자가 비유를 실제 동작으로 바꾸고 생략된 주체·조건·결과를 채워야 한다면 설명의 일부를 독자에게 떠넘긴 셈입니다.

이 저장소에는 다음 결과물이 있습니다.

- [브라우저에서 바로 읽는 실험 문서](docs/index.html)
- Claude Code와 Codex 등에서 사용할 수 있는 [`korean-technical-writing-review`](plugins/korean-technical-writing-review/skills/korean-technical-writing-review/SKILL.md) 스킬
- 공개 가능한 합성 사례 20개와 기대 판정으로 구성한 [평가 세트](evals/README.md)
- 공개 저장소 설치부터 실제 판정까지 확인한 [CLI 스모크 테스트](evals/cli-smoke/README.md)

- 실행 환경과 프롬프트 효과를 분리해 285회 반복한 [프롬프트 사다리 실험](evals/ollama-cloud/prompt-ladder/README.md)
- 스킬 발견·응답 완료·지침 효과를 분리해 168회 반복한 [스킬 효과 요인 실험](evals/skill-effect-v2/README.md)
- Codex용 플러그인 및 저장소 마켓플레이스 메타데이터

## 가장 짧은 사용법

Agent Skills를 지원하는 CLI에서는 다음 명령으로 설치할 수 있습니다.

```bash
npx skills add JooyoungChoi14/korean-technical-writing-for-llms --skill korean-technical-writing-review
```

설치 뒤에는 다음처럼 요청합니다.

```text
$korean-technical-writing-review 이 설계 문서를 검사하고, 의미를 확정할 수 있는 문장만 제한적으로 고쳐 주세요.
```

Codex 저장소 플러그인으로 사용할 때는 `.agents/plugins/marketplace.json`과 `plugins/`를 함께 사용합니다.

## 실제 CLI에서 확인한 동작

2026년 9월 2일 공개 GitHub 저장소에서 프로젝트 로컬 스킬로 새로 설치한 뒤, Claude Code와 Codex CLI의 두 모델씩에 같은 세 문장을 검사했습니다.

| CLI·모델 | 스킬 발견 | `그릇` 확인 | 명확한 문장 통과 | 권한 규칙 충돌 확인 | 종합 |
|---|---|---|---|---|---|
| Claude Code · Sonnet 4.5 | 통과 | 통과 | 통과 | 통과 | 통과 |
| Claude Code · Opus 5 | 통과 | 통과 | 통과 | 통과 | 통과 |
| Codex CLI · gpt-5.6-sol | 통과 | 통과 | 통과 | 통과 | 통과 |
| Codex CLI · gpt-5.3-codex-spark | 통과 | 통과 | 통과 | 실패 | 실패 |

Spark는 3번을 모호하다고 표시했지만 나열 순서와 `거부 우선`의 논리적 충돌을 해소하지 않은 수정안을 제시했습니다. 이 결과는 설치 호환성과 모델별 핵심 행동을 한 번씩 확인한 **스모크 테스트**입니다. 반복 실행을 비교한 성능 벤치마크는 아닙니다. 설치 명령, 실행 조건, 기대 판정과 실제 출력은 [`evals/cli-smoke/`](evals/cli-smoke/README.md)에 공개했습니다.

같은 날 Codex를 Ollama Cloud에 연결해 공개 모델 19개도 모델당 한 번씩 시험했습니다. 15개가 최종 응답을 만들었고, 엄격한 세 조건을 모두 만족한 것은 GLM 5.3과 GLM 5.3 Flash였습니다. 네 모델은 도구 스키마 또는 서비스 오류로 미채점 처리했습니다. 이는 모델 우열을 일반화하는 벤치마크가 아니라 현재 하네스의 설치·동작 회귀 시험입니다. 설정 예시, 전체 결과와 원출력은 [`evals/ollama-cloud/`](evals/ollama-cloud/README.md)에 있습니다.

후속 실험에서는 도구를 제거한 직접 API 호출로 19개 모델에 다섯 프롬프트 조건을 각각 3회 적용했습니다. 총 285회 중 API 오류는 없었으므로 최초 네 모델의 실패는 하네스 또는 당시 서비스 상태로 분리할 수 있었습니다. 내용 면에서는 일반 자체 점검·반례 지침이 기준선을 넘지 못했고, 과제의 구체적인 경계 사례를 직접 제시했을 때 완전 통과가 7회에서 21회로 늘었습니다. 공개 모델 카드의 추론·지시 준수·에이전트 벤치마크도 결합했지만, 소집단별 관계 방향이 달라 단일 성능 점수로 설명할 수 없었습니다. 따라서 현재 결과는 모델 능력, 과제 적합성, 프롬프트, 추론 설정과 제공자 구현의 상호작용으로 해석합니다. 전체 원자료와 해석은 [`prompt-ladder/`](evals/ollama-cloud/prompt-ladder/README.md)에 있습니다.

이어서 스킬을 발견한 사실과 지침 내용의 효과를 분리했습니다. 8개 모델에 개발 120회와 새 도메인의 보류 48회를 실행한 결과, 확실성·규칙 충돌 점검을 합친 후보는 보류 판단 정확도를 51.6%에서 56.3%로 높였지만 완료율이 낮아지고 근거 없는 구현 추가가 33.3%에서 36.7%로 늘었습니다. 사전 채택 기준을 통과하지 못했으므로 실제 스킬은 수정하지 않았습니다. 문항, 후보, 168개 원출력, 환경 실패와 채점은 [`skill-effect-v2/`](evals/skill-effect-v2/README.md)에 있습니다.

## 핵심 제안

1. **작성·재작성:** 원문 표현이 아니라 사실, 코드 식별자, 문서 구조를 보존합니다.
2. **검사:** 비유, 혼합어, 명사 나열 자체를 금지하지 않고 그 때문에 대상이나 동작이 빠졌는지 찾습니다.
3. **제한 교정:** 검사에서 표시된 문장만 고칩니다. 확정할 수 없는 뜻은 창작하지 않고 `[확인 필요]`로 남깁니다.
4. **의미 검증:** 자연스러움과 사실 보존을 별도로 판정합니다.

이 방식은 특정 모델을 판별하거나 비난하기 위한 것이 아닙니다. 생성 도구와 관계없이 문서가 독자에게 요구하는 추론을 줄이기 위한 편집 절차입니다.

## 공개 연구 범위

핵심 문체 연구의 분석과 결론은 저장소 안에서 직접 확인할 수 있는 새 표본을 기준으로 합니다.

- 블랙박스 과제 3개: 종합정보시스템 권한, 월말 매출 인식, 지역 정책 실험 분석
- 비교한 모델 2개: Claude Sonnet과 Codex gpt-5.4
- 모델 원출력 6편: 각 모델에 같은 과제를 한 번씩 적용
- 합성 회귀 사례 20개: 문제 문장 16개와 정상·반례 4개
- 평가 축 2개: 독해 명료성과 의미 보존

모델에는 문체 연구라는 목적을 알리지 않고, 복잡한 개념을 처음 읽는 개발자도 구현할 수 있게 설명하라고 요청했습니다. Gemini 2.5 Pro도 실행을 시도했지만 연결된 계정의 제품 라이선스 오류로 결과를 얻지 못해 비교에서 제외했습니다.

표본이 모델별 3편이고 반복 실행하지 않았으므로 모델의 일반적인 우열이나 세대 효과를 추정하지 않습니다. 공개 결과는 어려운 문서를 작성할 때 나타날 수 있는 실패 유형을 찾고, 이를 검사하는 하네스를 설계하기 위한 탐색적 관찰입니다.

CLI 설치 검증과 Ollama Cloud 실험은 이 핵심 표본과 구분한 후속 검증입니다. 전자는 설치·호출 호환성을 확인하고, 후자는 19개 모델에 다섯 조건을 3회씩 적용해 실행 환경 실패와 프롬프트 민감도를 분리합니다. 후속 실험도 하나의 짧은 과제에 한정되므로 모델의 일반적인 한국어 성능 순위로 해석하지 않습니다.

### 비공개 탐색과의 관계

이 문제는 처음에 사내 문서에서 어색한 표현을 발견하면서 시작됐습니다. 그러나 해당 문서와 발췌문은 공개 표본, 평가 사례, 모델 비교에 사용하지 않았습니다. 프로젝트명·조직 정보·내부 경로도 이 저장소에 포함하지 않았습니다. 따라서 현재 공개 연구는 새로 생성한 블랙박스 출력과 합성 회귀 사례만으로 독립적으로 검토할 수 있습니다.
