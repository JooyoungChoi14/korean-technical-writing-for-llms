# 의미 보존 검사

문체 개선과 사실 보존을 별도의 축으로 평가한다.

수정 전후에 다음을 대조한다.

1. **주체:** 같은 구성 요소나 사람이 동작하는가?
2. **방향:** 입력과 출력, 호출자와 피호출자, 송신자와 수신자가 바뀌지 않았는가?
3. **조건:** `항상`, `일부`, `동시에`, `이후`, `실패할 때` 같은 조건이 유지되는가?
4. **결과:** 저장, 노출, 취소, 반환, 차단 등 실제 효과가 같은가?
5. **범위:** 기존 기능 전체인지 특정 버전·환경·화면인지 유지되는가?
6. **확실성:** 가능성, 계획, 결정, 관찰을 서로 바꾸지 않았는가?
7. **식별자:** 코드 이름과 타입의 의미를 일반어로 잘못 바꾸지 않았는가?

원문에서 확인할 수 없는 정보를 자연스럽게 보이게 만들기 위해 추가하지 않는다.

```text
[확인 필요] `읽은 ID를 전달한다`의 주체가 화면인지 API 클라이언트인지 원문에서 확정되지 않습니다.
질문: 이 이벤트를 실제로 발행하는 모듈은 무엇입니까?
```

수정문이 더 자연스럽더라도 위 항목 하나가 달라졌다면 성공으로 판정하지 않는다.
